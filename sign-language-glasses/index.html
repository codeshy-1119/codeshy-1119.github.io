译言译行——聋哑人第一人称AI手语翻译眼镜

让无声世界「开口说话」

你有没有想过，当一个聋哑人在餐厅点餐、在车站问路、在药店买药时，他是怎么和健听人沟通的？

写纸条、比划、手机打字……这些都太慢、太别扭了。而真正阻碍他们的，不只是听不见，而是彼此之间没有一座「翻译」的桥。

这个项目「译言译行」就是想做这座桥：一副佩戴在聋哑人身上的 AI 手语翻译眼镜，从佩戴者的第一人称视角实时识别他的手语，并立刻语音播报出来，让对面的健听人「听懂」他在说什么。

一、项目背景

我国有数千万聋哑人，手语是他们最主要的沟通方式，但绝大多数健听人并不懂手语。传统手语翻译依赖人工翻译员，成本高、不普及；手机摄像头方案需要手持、对准、等待，使用体验很差。

现有方案的共同痛点是：没有一个能解放双手、从用户第一视角连续工作的方案。而「眼镜」正是最自然的载体——它戴在聋哑人头上，摄像头就是他眼睛的位置，他打手语时，摄像头天然地正对着他自己的手，无需任何手持操作。

因此我设计了一款可佩戴的第一人称手语识别眼镜，并配套完整的「数据采集 → 模型训练 → 实时识别 → 语音播报」技术链路。

二、项目简介

项目名称： 译言译行——聋哑人第一人称AI手语翻译眼镜

核心定位： 面向聋哑人，从第一人称视角识别手语并语音播报的智能可穿戴设备。

两种识别视角：

视角 摄像头位置 用途
第一人称（聋哑人视角） 眼镜上的 ESP32-CAM 识别聋哑人自己的手语，向健听人播报
第二人称（对方视角） 电脑/普通摄像头 识别对方的手语，向聋哑人展示文字结果

演示手势（第一版）：

  • 你好
  • 早上好

说明：当前版本作为技术原型，先跑通「你好 / 早上好」两个高频手势，验证「第一人称识别 + 语音播报」的完整链路；词汇量可以通过采集更多数据、继续训练持续扩充。

三、系统总体架构

整个系统分为硬件端和软件端两大部分：

│   ┌────────────────────────────────────────────┐     │
│   │           眼镜硬件（ESP32-CAM）              │     │
│   │   摄像头朝下对准双手（第一人称视角）          │     │
│   │   Wi-Fi 视频流  →  http://192.168.4.1:81    │     │
│   └───────────────────┬────────────────────────┘     │
└───────────────────────┼─────────────────────────────┘
                        │  MJPEG 视频流
                        ▼
┌─────────────────────────────────────────────────────┐

│   │ 帧获取/预处理│→│ MobileNetV2│→│ 分类头/置信度  │   │
│   │ ROI/肤色检测│ │ 特征提取    │ │ 阈值+去重      │   │

│                        │                            │

整体流程：

  1. ESP32-CAM 眼镜端通过 Wi-Fi 推流（http://192.168.4.1:81/stream）；
  2. PC 端读取视频流，进行 ROI 裁剪、肤色检测、动作检测；
  3. 使用 MobileNet V2 特征提取器（TF Hub 迁移学习） 提取图像特征；
  4. 送入训练好的分类模型（.pb 图）得到手势类别与置信度；
  5. 命中目标手势且置信度达标 → 触发 Windows SAPI 语音播报，并在画面上叠加识别结果。

四、硬件设计

眼镜硬件选用 ESP32-CAM 作为核心：

项目 说明
主控+摄像头 ESP32-CAM（OV2640，自带 Wi-Fi）
安装位置 固定在眼镜镜腿/镜框前端，镜头朝下对准双手
视角 第一人称视角，摄像头即佩戴者眼睛
推流方式 板载 MJPEG 视频流：http://192.168.4.1:81/stream
供电 移动电源/电池供电

为什么选择 ESP32-CAM：

  • 体积小、功耗低，适合可穿戴；
  • 自带 Wi-Fi，通过局域网把视频流推给 PC 处理，把重计算放在电脑端；
  • 价格便宜，适合原型迭代。

说明：识别模型运行在 PC 端（Windows），ESP32-CAM 只负责采集与推流。后续可以进一步做模型剪枝/量化，把推理下沉到眼镜端或边缘盒子，实现完全离线。

五、数据集构建

手语识别的数据是我自己录的。为了贴近真实佩戴场景，我覆盖了室内亮光、室内暗光、室外等不同光照，并用脚本把视频抽成帧。

数据集规模：

类别 训练图片（帧） 补充视频
你好（nihao） 3944 张 6 个
早上好（zaoshanghao） 3758 张 6 个

采集与预处理脚本：

  • video_to_frame_direct.py：视频直接抽帧；
  • (no_use)video-to-frame.py：早期抽帧脚本（已弃用）；
  • Split Test and Train.sh：按类别把图片划分到训练/测试目录；
  • handsegment.py：基于 HSV 色域做肤色分割，辅助定位手部区域。

抽帧命名形如 nihao_indoor1_frame_0000.jpg，其中 indoor1 / indoor_dark1 / outdoor1 代表不同场景，方便后续按场景分析模型在不同光照下的表现。

六、模型训练

1. 迁移学习（MobileNet V2 特征提取）

训练基于 TensorFlow 官方的 retrain.py 思路改造：

  1. 用 TF Hub 的 MobileNet V2 Feature Vector 作为特征提取器（预计算 bottleneck）；
  2. 在其输出之上训练一个全连接分类头；
  3. 输出 final_result:0，标签文件为 *_labels.txt。

核心流程代码（节选）：

feature_extractor = hub.load(TFHUB_CACHE_DIR + "/mobilenet-v2-tensorflow2-tf2-preview-feature-vector-v4")
feat_input = tf.compat.v1.placeholder(tf.float32, shape=(None, 224, 224, 3))
feat_output = feature_extractor(feat_input)

od_graph_def = tf.compat.v1.GraphDef()
with tf.io.gfile.GFile("cn_retrained_graph.pb", 'rb') as fid:
    od_graph_def.ParseFromString(fid.read())
    tf.import_graph_def(od_graph_def, name='')
# 分类模型输入/输出
input_tensor  = tf.compat.v1.get_default_graph().get_tensor_by_name('BottleneckInput:0')
output_tensor = tf.compat.v1.get_default_graph().get_tensor_by_name('final_result:0')

为了加速训练，我对每张图片预计算 bottleneck 特征缓存到磁盘（*.bottleneck.txt），避免重复跑特征提取。

2. 时序建模（RNN / LSTM）

手语是连续动作，单帧图像信息有限。项目里还实现了一条 CNN 特征 + LSTM 时序建模 的路线（rnn_train.py / rnn_utils.py）：

  • 先把每帧用 CNN 提取成特征序列；
  • 按视频窗口组织成 [num_frames, feature_size] 的序列；
  • 用两层 LSTM（TFLearn）学习手势的时序依赖；
  • 输出手势类别。
net = tflearn.input_data(shape=[None, frames, input_size])
net = tflearn.lstm(net, 128, dropout=0.8, return_seq=True)
net = tflearn.lstm(net, 128)
net = tflearn.fully_connected(net, num_classes, activation='softmax')
net = tflearn.regression(net, optimizer='adam', loss='categorical_crossentropy')

七、实时识别实现

实时识别在 Windows PC 上运行，主要脚本：

  • realtime_camera_speech.py：电脑摄像头实时识别 + 语音播报；
  • test_video_recognition.py / demonstration_camera.py：读取 ESP32 眼镜视频流 实时识别；
  • demonstration_show.py / demonstration_show1.py / demonstration_show2.py：演示用版本；
  • predict_spatial.py：第二人称视角识别 + 聊天式结果展示。

1. 识别主流程

读取视频帧
   │
   ├─ ROI 裁剪（聚焦手部区域）
   ├─ 肤色/动作检测（HSV + 帧差）
   │
   ▼
每隔 N 帧：MobileNetV2 提取特征 → 分类 → softmax 置信度
   │
   ▼
命中目标手势 且 置信度 ≥ 阈值 且 非锁定状态
   │
   ▼
异步触发 Windows TTS 语音播报 + 画面叠加识别结果
   │
   ▼
进入「动作锁定」防重复触发

2. 关键设计点

① 动作检测与防误触发

  • 用帧差法判断手部是否在动，无动作时不推理，省算力；
  • 手部进入 ROI 判断 + HSV 肤色检测过滤无关物体；
  • 要求连续多帧检测到手才触发（HAND_STABLE_FRAMES）；
  • 设置触发间隔（如 TRIGGER_INTERVAL = 2.5~3s），同一动作不重复播报。

② 动作锁定（防重复识别）

识别成功后进入锁定状态，ACTION_LOCK_DURATION（如 0.8~1.5s）内不再识别，避免一次手势播报多遍：

if action_locked and (time.time() - action_lock_timer) > ACTION_LOCK_DURATION:
    action_locked = False   # 超时解锁，可识别下一个动作

③ 置信度阈值

不同手势使用不同阈值（如「你好」50%、「早上好」20%），降低误报。

④ 帧率与性能优化

  • 多线程推理：后台线程负责 特征提取 + 分类，主线程只管取帧显示；
  • 队列只保留最新帧（maxsize=1），丢弃积压帧，保证实时性；
  • 每隔 N 帧处理一次（PROCESS_EVERY_N_FRAMES）；
  • 强制 CPU 推理（CUDA_VISIBLE_DEVICES=-1）+ 限制线程数，避免卡顿；
  • 推理缓存清理（CACHE_CLEAR_TIMES）解决视频流延迟。

⑤ 语音播报

基于 Windows SAPI（win32com.client.Dispatch("SAPI.SpVoice")），用异步线程 + 锁播报，不阻塞主循环：

speech_engine = win32com.client.Dispatch("SAPI.SpVoice")
speech_engine.Rate = 1
speech_engine.Volume = 100

def speak_async(text):
    threading.Thread(target=lambda: speech_engine.Speak(text), daemon=True).start()

⑥ 中文显示

OpenCV 原生不支持中文，画面叠加用 PIL + simhei.ttf（黑体） 绘制中文结果：

font = ImageFont.truetype("simhei.ttf", 30)
frame_pil = Image.fromarray(cv2.cvtColor(frame, cv2.COLOR_BGR2RGB))
ImageDraw.Draw(frame_pil).text((20, 20), f"识别到：{label}", font=font, fill=(0, 255, 0))

九、踩坑与优化记录

整个开发过程踩了不少坑，也总结了一些经验：

问题 解决方案
TF 2.x 与 TF 1.x 代码兼容 统一使用 tf.compat.v1 + disable_v2_behavior() / disable_eager_execution()
中文路径导致 TF Hub 缓存失败 设置 TFHUB_CACHE_DIR 指向无中文的路径（如 E:\...\tfhub_cache）
模型在线下载慢/失败 预下载模型到本地 tfhub_cache，代码改为本地加载
摄像头反复误触发 ROI 缩小 + HSV 肤色过滤 + 连续帧确认 + 触发间隔 + 动作锁定
视频流延迟、帧率低 多线程推理 + 只保留最新帧 + 每 N 帧处理 + 强制 CPU
语音播报卡主流程 异步线程 + threading.Lock 串行播报
OpenCV 中文乱码 改用 PIL + 中文字体（simhei.ttf / msyh.ttc）绘制
默认音频设备不对导致无声 启动时检查当前音频输出设备并给出提示

总结与展望

这个项目用「眼镜硬件 + 第一人称视角 + 迁移学习 + 语音播报」的路线，把传统需要手持、对准、等待的手语识别，做成了解放双手、即打即译的可穿戴体验，从根源上解决了聋哑人沟通时「对方听不懂」的问题。

当前成果：

  • ✅ ESP32-CAM 眼镜硬件原型，第一人称视角推流；
  • ✅ 自建「你好 / 早上好」数据集（室内亮/暗、室外多场景）；
  • ✅ MobileNetV2 迁移学习 + LSTM 时序建模双路线；
  • ✅ 实时识别 + 语音播报 + 画面叠加的完整闭环；
  • ✅ 第二人称视角识别 + 聊天式界面。

后续可以做的：

  • 扩充手语词汇库（更多高频词、常用句）；
  • 模型量化/剪枝，把推理下沉到眼镜端或边缘盒子，实现完全离线；
  • 从单帧分类升级为连续句子级识别（结合 LSTM 输出端到端序列）；
  • 接入更自然的交互（骨传导耳机、震动反馈、手机推送）。

无声世界不该被沉默定义。一副小小的眼镜，也许就是他们与世界对话的开始。
