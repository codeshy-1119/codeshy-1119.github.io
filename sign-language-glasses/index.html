译言译行——聋哑人第一人称AI手语翻译眼镜

周六 14 二月 2026 · 人工智能 · Tagged with 手语识别, 人工智能, 计算机视觉, 深度学习, TensorFlow, MediaPipe, ESP32

译言译行——聋哑人第一人称AI手语翻译眼镜（MediaPipe 版）

让无声世界「开口说话」 · V2：基于手部关键点的全新识别方案

你有没有想过，当一个聋哑人在餐厅点餐、在车站问路、在药店买药时，他是怎么和健听人沟通的？

写纸条、比划、手机打字……这些都太慢、太别扭了。而真正阻碍他们的，不只是听不见，而是彼此之间没有一座「翻译」的桥。

这个项目「译言译行」就是想做这座桥：一副佩戴在聋哑人身上的 AI 手语翻译眼镜，从佩戴者的第一人称视角实时识别他的手语，并立刻语音播报出来，让对面的健听人「听懂」他在说什么。

本文记录的是第二代（V2）方案——放弃第一代「整张图片 + CNN」的思路，改用 MediaPipe 手部关键点识别。新方案识别率显著更高、模型极小、CPU 就能毫秒级推理，是真正能戴在身上的版本。

一、项目背景

我国有数千万聋哑人，手语是他们最主要的沟通方式，但绝大多数健听人并不懂手语。传统手语翻译依赖人工翻译员，成本高、不普及；手机摄像头方案需要手持、对准、等待，使用体验很差。

现有方案的共同痛点是：没有一个能解放双手、从用户第一视角连续工作的方案。而「眼镜」正是最自然的载体——它戴在聋哑人头上，摄像头就是他眼睛的位置，他打手语时，摄像头天然地正对着他自己的手，无需任何手持操作。

因此我设计了一款可佩戴的第一人称手语识别眼镜，并配套完整的「数据采集 → 特征提取 → 模型训练 → 实时识别 → 语音播报」技术链路。

六、关键点数据集构建（V2 核心）

V2 的核心思路：不再用整张图片做特征，而是先让 MediaPipe Hands 把「手」抽成 21 个骨骼关键点，再用关键点训练分类器。

collect_landmarks.py 支持两种数据源：

提取流程：

  1. 读取图像/视频帧（BGR）；

七、关键点特征设计

MediaPipe Hands 每只手输出 21 个关键点，每个点有 $(x, y, z)$ 三个坐标。但原始坐标不能直接用，因为：

  • 手在画面中的位置会变（平移影响）；
  • 手离摄像头远近会变（尺度影响）；
  • 画面分辨率、摄像头不同也会带来差异。

因此 landmark_utils.py 里的 normalize_landmarks() 做了两步关键归一化：

1. 相对手腕（平移不变）

以手腕关键点（index 0）为原点，所有点减去手腕坐标：

$$ \mathbf{p}i' = \mathbf{p}_i - \mathbf{p}, \quad i = 0,1,\dots,20 $$}

这样手在画面里怎么移动都不影响特征。

2. 尺度归一化（尺度不变）

除以「手腕 → 中指根部」的距离 $d$，消除手大小和远近的影响：

$$ \mathbf{p}i'' = \frac{\mathbf{p}_i'}{d}, \quad d = |\mathbf{p}| $$}} - \mathbf{p}_{\text{wrist}

3. 可选深度 z

MediaPipe 提供了相对深度 $z$，对手势姿态判断有帮助。通过 config.FEAT_MODE 切换：

FEAT_MODE 维度 内容
rel 42 维 仅 $(dx, dy)$
rel_z 63 维 $(dx, dy, dz)$，含深度（默认） 
def normalize_landmarks(lmks, mode="rel_z"):
    lmks = np.asarray(lmks, dtype=np.float32).reshape(21, 3)
    wrist = lmks[0]
    rel = lmks - wrist                        # 相对手腕（平移不变）
    scale = float(np.linalg.norm(lmks[9] - lmks[0]))  # 手腕→中指根部 距离
    if scale < 1e-6:
        return None
    rel = rel / scale                          # 尺度归一化
    if mode == "rel":
        return rel[:, :2].flatten()             # 42 维
    return rel.flatten()                        # 63 维（含 z）

一句话总结：先以手腕为原点消除位置影响，再除以「手腕→中指根部」距离消除尺度影响，得到 63 维平移/尺度不变的手部姿态特征。

八、模型训练（轻量 MLP）

1. 网络结构

63 维特征不需要复杂网络，一个轻量 MLP 就足够：

model = keras.Sequential([
    keras.layers.Input(shape=(input_dim,)),      # 63 维关键点特征
    keras.layers.Dense(128, activation="relu"),
    keras.layers.BatchNormalization(),
    keras.layers.Dropout(0.3),
    keras.layers.Dense(64, activation="relu"),
    keras.layers.Dropout(0.3),
    keras.layers.Dense(num_classes, activation="softmax"),
])
model.compile(
    optimizer=keras.optimizers.Adam(learning_rate=1e-3),
    loss="sparse_categorical_crossentropy",
    metrics=["accuracy"],
)
  • 两层全连接（128 → 64）+ BatchNorm + Dropout(0.3)
  • 约 2 万参数，CPU 毫秒级推理
  • 输出类别 softmax

2. 数据增强

手语视频连续帧高度相似，直接训练容易过拟合。训练时对训练集做了高斯噪声增强 ×3 倍，提升鲁棒性：

def augment(Xb, yb, factor=3):
    Xs, ys = [Xb], [yb]
    rng = np.random.default_rng(0)
    for _ in range(factor - 1):
        noise = rng.normal(0, 0.02, Xb.shape).astype(np.float32)  # σ=0.02
        Xs.append(Xb + noise)
        ys.append(yb)
    return np.vstack(Xs), np.concatenate(ys)

九、实时识别实现

实时识别入口：mediapipe_gesture/recognize_realtime.py，支持本地摄像头 / 手机虚拟摄像头 / ESP32 眼镜流，识别时实时绘制绿色骨骼，命中即语音播报。

1. 主循环流程

读取一帧 → 镜像翻转（操作更直观）
   │
   ▼
MediaPipe Hands 提取手部关键点（流式模式，更快）
   │
   ▼
关键点归一化 → MLP 预测 → softmax 得到「你好/早上好」置信度
   │
   ▼
置信度 ≥ CONF_THRESHOLD（70%）？→ 是则 countdown+1，否则清零
   │
   ▼
连续 CONTINUOUS_FRAMES（3）帧达标 → 触发！
   │
   ▼
异步语音播报 + 进入动作锁定（1.5s 防重复）
   │
   ▼
画面叠加：类别+置信度（绿）/ 状态栏（识别中/锁定中）

2. 关键设计点

① 连续帧确认（防误触发）

单帧命中置信度不算数，必须连续 3 帧都超过阈值才触发，显著减少误报：

if conf >= config.CONF_THRESHOLD:
    countdown += 1          # 连续达标帧数 +1
else:
    countdown = 0           # 一旦不达标就清零
if countdown >= config.CONTINUOUS_FRAMES:
    # 触发识别
    speak_async(label)
    action_locked = True

② 动作锁定（防重复播报）

触发一次后锁定 ACTION_LOCK_DURATION（1.5 秒），锁定期间只显示预测不播报，避免同一个手势反复播报：

if action_locked and (now - lock_timer) > config.ACTION_LOCK_DURATION:
    action_locked = False   # 超时解锁

③ 语音播报（Windows SAPI + 自动选音）

用 Windows SAPI 异步播报，不阻塞主循环；并且自动挑选发音最好的中文语音（优先 Neural/Online 神经网络语音，如晓晓 Xiaoxiao）：

def pick_best_voice(engine):
    def score(v):
        desc = v.GetDescription(); s = 0
        if any(k in desc for k in ("Natural", "Neural", "Online")): s += 10
        if any(k in desc for k in ("Xiaoxiao", "Xiaoyi", "Yunxi", "Yunyang")): s += 5
        if any(k in desc for k in ("Chinese", "zh-CN", "中文")): s += 3
        return s
    return max(engine.GetVoices(), key=score)

④ 手部骨骼可视化

把 21 个关键点按 MediaPipe 定义的骨架连接（HAND_CONNECTIONS）用绿色线条实时画在画面上，直观展示检测到手的效果：

for a, b in HAND_CONNECTIONS:
    cv2.line(frame, pts[a], pts[b], (0, 255, 0), 2)
for px, py in pts.values():
    cv2.circle(frame, (px, py), 3, (0, 255, 0), -1)

⑤ 摄像头后端优化

Windows 下用 DirectShow 后端（cv2.CAP_DSHOW）打开摄像头，对 USB/虚拟摄像头更稳定、延迟更低；ESP32 流则用 cv2.CAP_FFMPEG。

⑥ 交互细节

  • 画面镜像翻转，操作更直观；
  • 右上角状态栏：识别中（绿）/ 锁定中（红）；
  • 按 Q 退出，按 R 手动解锁。

十、环境准备与踩坑记录

MediaPipe 方案的环境坑不少，这里完整记录，方便复现。

1. numpy 必须 < 2（最关键！）

mediapipe 0.10.5 和 TensorFlow 2.13 都是按 numpy 1.x 编译的，装 numpy 2 会直接崩溃：

pip install "numpy==1.26.4"

2. mediapipe 中文路径 bug（Windows）

mediapipe 装在 C:\Users\中文用户名\... 这种含中文的路径下，初始化会报 FileNotFoundError。这是 mediapipe 在 Windows 上对非 ASCII 路径的已知 bug。

解决方案：项目内放了一份纯 ASCII 路径的 mediapipe 副本 vendor/mediapipe，landmark_utils.py 会自动优先从 vendor/ 加载：

_VENDOR_DIR = os.path.join(项目根, "vendor")
if _VENDOR_DIR not in sys.path:
    sys.path.insert(0, _VENDOR_DIR)   # 优先用 ASCII 路径副本

3. 语音依赖

pip install pywin32

4. 控制台中文/emoji 乱码

Windows 控制台默认 GBK，打印 emoji 会报错。脚本开头强制 UTF-8：

if hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")

问题 解决方案

项目内 docs/ 包含两个 HTML 原型，用于预演后续把识别能力封装成手机 App 的界面：

  • 摄像界面.html：相机识别页（取景框 + 识别结果 + 语音开关）。

十四、旧方案回顾（V1：CNN 图像方案）

V1 是「整张图片 + CNN」的思路，虽然跑通了链路，但识别率低、模型大、受光照和背景干扰严重，因此被 V2 取代。旧代码全部保留在 legacy/，git 分支 backup-pre-mediapipe（commit e8401d8）和物理备份 backup_pre_mediapipe/ 都可以随时回退。

V1 技术路线：

  1. 迁移学习：用 TF Hub 的 MobileNet V2 Feature Vector 提取图像特征，预计算 bottleneck 缓存到磁盘，再训练分类头（retrain.py）；
  2. 时序建模：CNN 特征 + 两层 LSTM（TFLearn）学习手势时序依赖（rnn_train.py / rnn_utils.py）；
  3. 实时识别：ROI + 肤色/帧差动作检测 + 多线程推理 + SAPI 语音（realtime_camera_speech.py 等）。

V1 训练产物（保留在 legacy/models）：

模型文件 标签 用途
cn_retrained_graph.pb 你好/非你好 第一人称实时识别
two_gesture_model.pb 你好/早上好 双手势识别
cn_secondperson_sign_recognizer.pb 你好/非你好 第二人称视角识别

一句话总结 V1→V2：V1 用「整图卷积特征」学手势，既慢又容易受环境干扰；V2 改走「MediaPipe 先抽手部骨骼关键点、再用轻量 MLP 分类」的路线，识别率从“低”提升到测试集 85%，并且 CPU 毫秒级、可穿戴。

总结与展望

这个项目用「眼镜硬件 + 第一人称视角 + MediaPipe 关键点 + 语音播报」的路线，把传统需要手持、对准、等待的手语识别，做成了解放双手、即打即译的可穿戴体验，从根源上解决了聋哑人沟通时「对方听不懂」的问题。

当前成果（V2）：

  • ✅ ESP32-CAM 眼镜硬件原型，第一人称视角推流；
  • ✅ 自建第一人称手势数据集（室内亮/暗、室外多场景，3944+3758 张）；
  • ✅ MediaPipe 21 关键点 → 63 维归一化特征 → 轻量 MLP（约 2 万参数）；
  • ✅ 测试集准确率 85%，最高验证准确率 88.74%；
  • ✅ 实时识别 + 绿色骨骼可视化 + 语音播报完整闭环；
  • ✅ deliver_training/ 自包含交付包，可复现训练与消融实验。

后续可以做的：

  • 动态手势（时序）：采集时保存关键点序列，改用 LSTM/GRU 或 TFLite 时序模型，识别连续动作；
  • 左右手：HAND_MAX_HANDS 已支持多手，可扩展双手同时比划的场景；
  • 硬件部署：Keras 模型导出 TFLite，部署到树莓派等边缘设备，彻底离线；
  • 扩充词汇：采集更多高频词/常用句，提升模型泛化；
  • 交互升级：骨传导耳机、震动反馈、手机推送。

无声世界不该被沉默定义。一副小小的眼镜，也许就是他们与世界对话的开始。
