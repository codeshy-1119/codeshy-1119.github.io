网络培训笔记：从交换到高可用的全栈知识体系

周六 01 八月 2026 · 技术 · Tagged with NE，高级交换

第一天

核心内容：OSI模型、IP地址基础、ARP/TCP/UDP协议、基础CLI命令、远程管理配置

一、网络基础概念

1. 网络拓扑

拓扑就是网络设备的连接图： - 星型：扩展性好，可靠性差。 - 全网状：扩展性差，可靠性好。 - 双星型：均衡（常用）。

📌 一句话总结：拓扑是网络设备的连接图，常见有星型、全网状和双星型，双星型是可靠性、扩展性最均衡的常用方案。

2. OSI参考模型（七层）

分层的意义：每一层各司其职，降低复杂度，利于升级和排障。 - 发送方：从应用层往下，逐层封装数据。 - 接收方：从物理层往上，逐层解封装获取数据。

层级 名称 核心设备/功能
1 物理层 传输比特流（网线电信号、光纤光信号、无线电磁波），设备：调制解调器（光猫）
2 数据链路层 根据 MAC地址 进行转发，设备：交换机。交换机不能划分广播域，负责广播域内通信
3 网络层 根据 IP地址 进行转发，设备：路由器。路由器可以划分广播域，负责广播域间通信（选路）
4-7 传输层及以上 TCP/UDP（传输层）、会话、表示、应用层

📌 一句话总结：OSI七层模型（物理层、数据链路层、网络层、传输层、会话层、表示层、应用层）规定了数据从发送方逐层封装、接收方逐层解封装的标准，确保不同厂商设备可以互操作；其中交换机工作在数据链路层（基于MAC转发，不能划分广播域），路由器工作在网络层（基于IP转发，能划分广播域）。

3. 关键术语辨析

  • 冲突域：交换机和路由器都能解决冲突。有线网络因交换机普及已无冲突问题，无线网络仍存在。
  • 广播域：路由器可以划分广播域。广播域不宜过大，否则会出现广播风暴。

📌 一句话总结：交换机可以解决冲突域问题，路由器可以划分广播域，广播域过大会导致广播风暴。

二、IP地址与子网掩码

  • IP地址：逻辑地址（可变化），起门牌号作用。
  • 子网掩码：用于确定IP地址的哪些位是网络位，哪些是主机位。
  • 网络位一致的IP地址，属于同一网段 = 同一子网 = 同一广播域。

📌 一句话总结：IP地址是逻辑地址（可变化），子网掩码决定网络位和主机位，网络位相同则属于同一网段（同一广播域）。

IPv4通信三种方式

  1. 单播：一对一。
  2. 组播：一对一组。
  3. 广播：一对所有（通常用于查找，无实际通信意义）。

📌 一句话总结：单播是一对一，组播是一对一组，广播是一对所有（通常用于查找，无实际通信意义）。

三、ARP协议（地址解析协议）

作用：将IP地址解析为MAC地址（有缓存直接用，无缓存广播找，单播回）。

工作流程（主机A与主机B通信）： 0. A判断B是否在同一广播域（是则查B的MAC，否则查网关的MAC）。 1. A查ARP缓存表，若无B的MAC记录。 2. A广播发送ARP查询（请求192.168.1.2的MAC）。 3. B收到后记录A的IP-MAC映射，并单播回应自己的MAC。 4. A更新缓存表，封装数据包并发送。

📌 一句话总结：ARP用于将IP地址解析为MAC地址，流程是"有缓存直接用，无缓存广播找，目标单播回"。

免费ARP

主机使用IP前，广播询问该IP对应的MAC。无回应 = IP不冲突；有回应 = IP冲突，需重新获取地址。

📌 一句话总结：主机使用IP前广播询问该IP对应的MAC，无回应表示IP不冲突，有回应表示IP冲突需重新获取。

四、传输层协议（TCP / UDP）

特性 TCP（面向连接） UDP（无连接）
特点 可靠传输 尽力而为（快）
适用场景 邮件、下载、刷抖音 游戏、音视频、直播
核心机制 三次握手、四次挥手、分段重组、重传、窗口大小（流量控制） 有分段，但无重组、重传、窗口大小

📌 一句话总结：TCP是面向连接的可靠传输（有三次握手、重传、窗口机制），适用于邮件、下载等场景；UDP是无连接的尽力传输（快但无重传），适用于游戏、音视频、直播等场景。

端口号（0-65535）

  • 0-1023（知名端口）：80(HTTP)、22(SSH)、23(Telnet)、53(DNS)、25(SMTP)、443(HTTPS)、20/21(FTP)
  • 注册端口：3389(RDP)、3306(MySQL)、1812/1813(Radius)
  • 动态端口：临时分配，用完归还

    源端口号是随机的，目的端口号通常是知名端口号。

📌 一句话总结：端口号范围0-65535，其中0-1023为知名端口（如80-HTTP、23-Telnet、53-DNS），源端口随机生成，目的端口通常为知名端口。

第二天

核心内容：交换机转发原理、VLAN概念、Access/Trunk接口、文件管理与FTP备份

一、交换机转发原理

交换机依据 MAC地址表 进行转发，MAC地址表记录 MAC地址 ↔ 接口 的映射关系。

行为 说明
学习 收到数据帧的源MAC + 接收接口 → 自动生成MAC表项
泛洪 目标MAC不在表中，交换机向所有接口（除接收口外）广播发送
转发 目标MAC在表中，交换机从对应接口发出
更新 （1）后到优先（新记录覆盖旧记录）；（2）老化时间 300秒

📌 一句话总结：交换机依据MAC地址表转发，收到帧时学习源MAC与接口的映射，目标MAC未知则泛洪，已知则从对应接口转发，MAC表老化时间为300秒。

二、VLAN技术（虚拟局域网）

作用：在交换机上划分广播域，实现二层隔离。

VLAN优点

  1. 减少广播流量，提高带宽利用率。
  2. 不同广播域不能直接通信，提升安全性（防ARP欺骗等）。
  3. 不受物理位置限制，组网更灵活。

📌 一句话总结：VLAN在交换机上划分广播域，实现二层隔离，能减少广播流量、提升安全性和组网灵活性。

802.1Q封装

PC不识别VLAN Tag，数据进入交换机时，会打上 VLAN Tag（标签）标识属于哪个VLAN。最常见的划分方式是基于接口划分VLAN。

📌 一句话总结：PC不识别VLAN Tag，数据进入交换机时会打上802.1Q封装的VLAN Tag标签标识所属VLAN。

交换机接口类型

接口类型 连接对象 VLAN通过 数据帧Tag特征
Access 终端设备（PC） 只允许1个VLAN 收发数据通常不带Tag
Trunk 网络设备（交换机/路由器） 允许多个VLAN 收发数据通常带Tag（PVID除外）
Hybrid 终端或网络设备均可 允许多个VLAN 可自定义哪些VLAN带Tag，哪些不带

PVID特点：每个接口只能有一个PVID，Trunk两端PVID必须一致。

📌 一句话总结：Access接口只允许一个VLAN通过且不带Tag（接终端），Trunk接口允许多个VLAN通过且通常带Tag（接网络设备），Hybrid接口可自定义哪些VLAN带/不带Tag（华为/华三特色接口）；Trunk的PVID两端必须一致，华为/华三Trunk默认只允许VLAN 1，思科/锐捷默认允许所有VLAN。

三、VLAN配置命令

1. 创建VLAN与命名

[S1] display vlan brief          # 查看VLAN摘要
[S1] vlan 10
[S1-vlan10] name IT              # 命名VLAN 10为IT
[S1] vlan 20
[S1-vlan20] name CW

2. 接口划分VLAN（两种方法）

方法一（接口视图配置）：

[S1] interface GigabitEthernet 1/0/1
[S1-GigabitEthernet1/0/1] port link-type access
[S1-GigabitEthernet1/0/1] port access vlan 10

方法二（VLAN视图下添加接口）：

[S1] vlan 20
[S1-vlan20] port GigabitEthernet 1/0/2

批量配置：

[S1] interface range GigabitEthernet 1/0/10 to GigabitEthernet 1/0/20
[S1-if-range] port link-type access
[S1-if-range] port access vlan 10

3. Trunk接口配置

[S1] interface GigabitEthernet 1/0/3
[S1-GigabitEthernet1/0/3] port link-type trunk
[S1-GigabitEthernet1/0/3] port trunk permit vlan 10 20    # 允许VLAN 10和20通过
[S1-GigabitEthernet1/0/3] port trunk pvid vlan 10         # 调整PVID（默认不需调整）

注意：华为/华三的Trunk默认只允许VLAN 1；思科/锐捷默认允许所有VLAN。

[S1] display port trunk          # 查看Trunk接口状态

📌 一句话总结：通过vlan命令创建VLAN并命名，使用port link-type access + port access vlan将接口划入VLAN，使用port link-type trunk + port trunk permit vlan允许VLAN通过Trunk。

第三天

核心内容：STP产生背景、工作原理、端口状态、收敛机制、Hybrid接口详解与实验

一、STP（生成树协议）产生背景

1. 环路产生原因

  • 管理员误操作。
  • 为了可靠性设计的冗余网络结构。

2. 环路危害

  1. 广播流量无终止循环，严重占用带宽，可能导致断网。
  2. 交换机MAC地址表不断抖动，CPU高负载，可能宕机。
  3. PC频繁处理广播信息，导致终端卡顿。

3. 解决方案

在所有交换机上运行STP，自动计算并逻辑拥塞（Block）某些接口以破除环路；当物理链路故障时，拥塞接口可重新转发（具备一定的可靠性），起备用路径作用。

📌 一句话总结：STP用于解决二层网络中因冗余链路或误操作导致的广播风暴、MAC地址表抖动和终端卡顿问题，通过逻辑拥塞接口破除环路。

二、STP工作原理（选路规则）

关键字段： - 桥ID = 优先级（默认32768，以4096倍数增减）+ MAC地址。 - 路径开销：根据带宽计算，带宽越大开销越小。 - 根路径开销：从本设备到根桥的所有路径开销之和。

选举四步曲

  1. 选根桥：桥ID最小的设备。
  2. 选根端口（RP）（每台非根交换机上选1个）：
  3. （1）根路径开销最小（从接口出发）；
  4. （2）对端桥ID最小；
  5. （3）对端端口ID最小。
  6. 选指定端口（DP）：
  7. 根桥上的所有端口都是DP；
  8. 每条链路两端必有一端为DP；
  9. 选法：（1）根路径开销最小（从设备出发）；（2）桥ID最小；（3）端口ID最小。
  10. 剩余端口为拥塞端口（Block）。

📌 一句话总结：STP选举过程分四步——先选桥ID最小的根桥，再在每台非根交换机上选根路径开销最小+对端桥ID最小+对端端口ID最小的根端口，然后选根路径开销最小+桥ID最小+端口ID最小的指定端口（根桥上所有端口均为指定端口），剩余端口为拥塞端口。

BPDU（桥协议数据单元）

  • 携带桥ID、路径开销等信息。
  • 根桥选举后，仅根桥每2秒发送BPDU，其他设备只作中转。
  • 指定端口发BPDU，根端口收BPDU。

📌 一句话总结：BPDU携带桥ID和路径开销等信息，根桥选举后仅根桥每2秒发送BPDU，其他设备仅作中转，指定端口负责发送、根端口负责接收。

三、STP端口状态与收敛时间

状态 说明 耗时
disable 接口关闭（shutdown） -
blocking 拥塞，不收发数据，但接收BPDU -
listening 进行端口角色选举 15秒
learning 学习MAC地址表（不转发数据） 15秒
forwarding 正常转发 -

一个正常接口从Down到转发，至少需要 30秒（Listening 15s + Learning 15s）。

故障收敛时间

  • 直连故障：30秒（拥塞接口所在交换机直连线路故障，直接感知拓扑变化）。
  • 非直连故障：50秒（20秒BPDU超时 + 30秒重新运算）。

📌 一句话总结：STP端口有disable、blocking、listening(15s)、learning(15s)、forwarding五种状态，正常接口从Down到转发需30秒；直连故障收敛需30秒，非直连故障需50秒（20秒BPDU超时+30秒重新运算）。

基础STP配置命令

[S1] undo stp global enable          # 全局关闭STP（不推荐）
[S1] stp mode stp                    # 切换为STP模式（默认MSTP）
[S3] stp priority 0                  # 调整优先级，使该设备成为根桥
[S1] display stp brief               # 查看生成树简要信息

📌 一句话总结：使用stp mode stp切换模式、stp priority调整优先级使设备成为根桥、display stp brief查看生成树状态，不推荐全局关闭STP。

四、Hybrid接口（混合接口）详解与实验

Hybrid接口是华为/华三的特色接口，兼具Access和Trunk特性：可连接终端，也可连接设备；可传输多个VLAN；能自定义哪些VLAN带Tag，哪些不带Tag。

📌 一句话总结：Hybrid接口兼具Access和Trunk特性，通过port hybrid pvid vlan设置缺省VLAN、port hybrid vlan X tagged/untagged自定义各VLAN发送时是否携带Tag，可实现终端与设备混合连接且灵活控制Tag行为。

实验拓扑（S1 —— S2，两台交换机）

需求：PC1（VLAN10）、PC2（VLAN20）都能访问服务器（VLAN100），但PC1与PC2二层隔离。

S1配置：

[S1] vlan 10
[S1] vlan 20
[S1] vlan 100

[S1] interface GigabitEthernet 1/0/1
[S1-GigabitEthernet1/0/1] port link-type hybrid
[S1-GigabitEthernet1/0/1] port hybrid pvid vlan 10                # PC无Tag进入，打上VLAN10
[S1-GigabitEthernet1/0/1] port hybrid vlan 10 100 untagged        # 允许VLAN10和100，发出时剥除Tag

[S1] interface GigabitEthernet 1/0/2
[S1-GigabitEthernet1/0/2] port link-type hybrid
[S1-GigabitEthernet1/0/2] port hybrid pvid vlan 20
[S1-GigabitEthernet1/0/2] port hybrid vlan 20 100 untagged

[S1] interface GigabitEthernet 1/0/3
[S1-GigabitEthernet1/0/3] port link-type hybrid
[S1-GigabitEthernet1/0/3] port hybrid vlan 10 20 100 tagged       # 互联接口，全部带Tag发送

S2配置：

[S2] vlan 10
[S2] vlan 20
[S2] vlan 100

[S2] interface GigabitEthernet 1/0/1
[S2-GigabitEthernet1/0/1] port link-type hybrid
[S2-GigabitEthernet1/0/1] port hybrid pvid vlan 100               # 服务器接口

第四天

核心内容：路由表原理、静态/默认路由配置、浮动路由、负载分担

一、路由表基础

路由器依据路由表进行转发，无匹配路径则丢弃。

路由表的五大要素

  1. 目标网段（要到达的目的网段）。
  2. 出接口（从本设备哪个接口发出）。
  3. 下一跳（下一台设备的IP地址，推荐使用）。
  4. 优先级（网络协议的优先程度，数值越小越优，不同协议间比较）。
  5. 度量值（路径优劣程度，数值越小越优，同协议内比较）。

选路规则：先比优先级，再比度量值。

📌 一句话总结：路由器依据路由表转发，路由表由目标网段、出接口、下一跳、优先级（数值越小越优）和度量值（数值越小越优）五大要素组成，选路时先比优先级再比度量值。

路由表产生方式

方式 特点
直连路由 自动出现
静态路由 管理员手工配置；适合小型网络；不消耗资源；安全性高；无法自适应变化
动态路由 路由器间自动交换；适合中大型网络；消耗资源；可自适应变化

📌 一句话总结：直连路由自动出现，静态路由由管理员手工配置（适合小型网络、不消耗资源、安全性高但无法自适应变化），动态路由由路由器间自动交换产生（适合中大型网络、消耗资源但可自适应变化）。

路由匹配原则：最长子网掩码匹配原则（掩码最长的条目优先使用）。

📌 一句话总结：路由器采用最长子网掩码匹配原则，即掩码最长的路由条目优先使用。

二、静态路由配置

场景：R1连接三层交换机S2，需访问S2下挂的PC网段

S2配置地址（三层接口）：

  • 方法一（接口切换为路由模式）： bash [S2] interface GigabitEthernet 1/0/3 [S2-GigabitEthernet1/0/3] port link-mode route [S2-GigabitEthernet1/0/3] ip address 192.168.15.5 24

  • 方法二（VLANIF方式，推荐）： bash [S2] vlan 999 [S2] interface GigabitEthernet 1/0/3 [S2-GigabitEthernet1/0/3] port link-type access [S2-GigabitEthernet1/0/3] port access vlan 999 [S2] interface Vlan-interface 999 [S2-Vlan-interface999] ip address 192.168.15.5 24

配置静态路由

[R1] ip route-static 192.168.60.0 24 192.168.15.5
[R1] ip route-static 192.168.70.0 24 192.168.15.5
[S2] ip route-static 192.168.10.0 24 192.168.15.1
[S2] ip route-static 192.168.20.0 24 192.168.15.1    # 回包路由（静态路由是单向的）

[R1] display ip routing-table        # 查看路由表

📌 一句话总结：使用ip route-static 目标网段 掩码 下一跳地址配置静态路由，需注意静态路由是单向的，必须配置回包路由才能实现双向通信。

三、默认路由（0.0.0.0/0）

特点：可匹配所有目标网络；遵循最长掩码匹配原则，最后才使用。

使用场景

  1. 访问外网：内网所有路由器需配置默认路由（逐跳转发）。默认路由访外网，明细路由访内网。
  2. 只有一个出口的末端网络。
  3. 电脑的网关。

注意事项

  • 默认路由不能互指，否则产生路由环路。
  • 多运营商出口时，可配合浮动静态实现主备。

📌 一句话总结：默认路由（0.0.0.0/0）能匹配所有目标网络，遵循最长掩码匹配原则最后才使用，适用于访问外网、末端网络和电脑网关场景，但不能互指否则会产生路由环路。

四、负载分担与浮动静态路由

负载分担

当两条路由去往同一目的网段，且优先级和度量值均相同时，同时加入路由表，实现流量分担。

[R1] ip route-static 192.168.60.0 24 192.168.15.5
[R1] ip route-static 192.168.60.0 24 192.168.18.8   # 两条等价，自动负载分担

📌 一句话总结：当两条路由去往同一目的网段且优先级和度量值均相同时，同时加入路由表实现流量负载分担。

浮动静态路由（主备路径）

[R1] ip route-static 192.168.60.0 24 192.168.15.5
[R1] ip route-static 192.168.60.0 24 192.168.18.8 preference 80   # 优先级调大，作为备份

默认情况下，只有最优路径加入路由表。若主链路故障，备用路径（浮动路由）自动浮现。

📌 一句话总结：通过配置两条去往同一目的网段但优先级不同的静态路由，高优先级（数值小）为主路径，低优先级（数值大）为备份路径，主链路故障时备份自动浮现。

第五天

核心内容：路由协议分类、OSPF原理与多区域配置、单臂路由、VLANIF配置

一、路由协议分类

按工作范围分

  • IGP（内部网关协议）：组织机构内部使用，如 RIP、OSPF、IS-IS、EIGRP。
  • EGP（外部网关协议）：组织机构之间互联，如 BGP。

按算法分

  • 距离矢量路由协议：RIP、BGP。RIP以跳数为度量（不综合考虑带宽）。
  • 链路状态路由协议：OSPF、IS-IS。OSPF以带宽为度量，更科学。

📌 一句话总结：按工作范围分为IGP（内部网关协议，如OSPF、RIP）和EGP（外部网关协议，如BGP）；按算法分为距离矢量（RIP以跳数为度量）和链路状态（OSPF以带宽为度量，更科学）。

二、OSPF协议详解

核心概念

  • LSA（链路状态通告）：每台路由器将自己的直连信息整理成LSA发给邻居。
  • LSDB（链路状态数据库）：全网所有LSA的集合。

📌 一句话总结：每台路由器将自己的直连信息整理成LSA发给邻居，全网所有LSA集合形成LSDB，路由器基于LSDB计算出最优路径。

DR（指定路由器）选举

目的：在广播域中减少重复的LSA更新。所有路由器只与DR/BDR建立邻接关系。

选举规则： 1. OSPF优先级（越大越优，默认为1，0表示不参与选举）。 2. Router-ID（越大越优）。

原则：非抢占原则（DR选定后，即使新加入更高优先级设备，也不重新选举）。

📌 一句话总结：在广播域中选举DR和BDR以减少重复的LSA更新，选举规则先比OSPF优先级（越大越优，0表示不参与）再比Router-ID（越大越优），遵循非抢占原则（DR选定后不重新选举）。

OSPF基础配置

[R1] ospf 1                                    # 启动OSPF，进程号本地有效
[R1-ospf-1] area 0
[R1-ospf-1-area-0.0.0.0] network 192.168.12.0 0.0.0.255   # 宣告网段（使用反掩码）
[R1-ospf-1-area-0.0.0.0] network 10.1.1.1 0.0.0.0         # 宣告主机地址

宣告的两层含义：（1）该网段以LSA发布到OSPF网络；（2）该接口收发OSPF报文，建立邻居。因此所有直连网段都需要宣告。

📌 一句话总结：使用ospf 1启动OSPF进程，进入area区域后用network 网段 反掩码宣告直连网段，宣告的含义是既发布路由信息也在该接口收发OSPF报文建立邻居。

常用查看与调整命令

[R3] display ospf peer                         # 查看OSPF邻居

# 调整Router-ID
[R3] ospf 1 router-id 33.33.33.33
<R3> reset ospf process                        # 重启进程使ID生效（会断网！）

# 调整DR优先级（基于接口）
[R5] interface GigabitEthernet 0/0
[R5-GigabitEthernet0/0] ospf dr-priority 100

📌 一句话总结：display ospf peer查看邻居，ospf router-id调整Router-ID（需reset ospf process重启进程生效，会中断网络），ospf dr-priority调整接口DR选举优先级。

多区域OSPF配置

多区域可减轻大型网络设备运算压力。区域间互通无需额外操作。

[R1] ospf 1
[R1-ospf-1] area 0
[R1-ospf-1-area-0.0.0.0] network 10.1.1.1 0.0.0.0
[R1-ospf-1-area-0.0.0.0] network 192.168.12.0 0.0.0.255
[R1-ospf-1] area 1
[R1-ospf-1-area-0.0.0.1] network 192.168.145.0 0.0.0.255

📌 一句话总结：在边界路由器上分别进入不同区域宣告对应网段即可实现多区域OSPF，区域间互通无需额外配置，多区域能减轻大型网络中设备的运算压力。

OSPF开销调整（影响选路）

# 方法一：调整参考带宽（所有设备需一致）
[R1] ospf 1
[R1-ospf-1] bandwidth-reference 10000

# 方法二：直接修改接口开销
[R1] interface GigabitEthernet 0/1
[R1-GigabitEthernet0/1] ospf cost 30

📌 一句话总结：通过bandwidth-reference调整参考带宽（所有设备需一致）或直接在接口下用ospf cost修改开销值，可以影响OSPF的路径选择。

三、VLAN间路由

1. 单臂路由（路由器子接口）

适用场景：使用路由器作为VLAN网关，通过一个物理接口划分多个子接口，每个子接口对应一个VLAN网关。交换机侧配置Trunk，根据VLAN Tag决定进入哪个子接口。

交换机配置（二层）：

[H3C] vlan 10
[H3C-vlan10] port GigabitEthernet 1/0/1
[H3C] vlan 20
[H3C-vlan20] port GigabitEthernet 1/0/2
[H3C] interface GigabitEthernet 1/0/3
[H3C-GigabitEthernet1/0/3] port link-type trunk
[H3C-GigabitEthernet1/0/3] port trunk permit vlan 10 20

路由器子接口配置：

[R1] interface GigabitEthernet 0/0.1
[R1-GigabitEthernet0/0.1] vlan-type dot1q vid 10
[R1-GigabitEthernet0/0.1] ip address 192.168.10.1 24

[R1] interface GigabitEthernet 0/0.2
[R1-GigabitEthernet0/0.2] vlan-type dot1q vid 20
[R1-GigabitEthernet0/0.2] ip address 192.168.20.1 24

📌 一句话总结：在路由器一个物理接口上划分多个子接口，每个子接口通过vlan-type dot1q vid绑定一个VLAN并配置对应网关地址，交换机侧配置Trunk，根据VLAN Tag决定进入哪个子接口实现VLAN间通信。

2. VLANIF（三层交换机）

三层交换机可同时实现交换与路由功能。先在物理接口划分VLAN，再创建虚拟的 VLANIF接口 作为网关。

配置条件：（1）设备存在该VLAN；（2）有接口能传输该VLAN（接口不能Down）。

[S2] vlan 60
[S2-vlan60] port GigabitEthernet 1/0/1
[S2] vlan 70
[S2-vlan70] port GigabitEthernet 1/0/2
[S2] interface Vlan-interface 60
[S2-Vlan-interface60] ip address 192.168.60.1 24
[S2] interface Vlan-interface 70
[S2-Vlan-interface70] ip address 192.168.70.1 24

📌 一句话总结：三层交换机在物理接口划分VLAN后，创建虚拟的Vlan-interface接口并配置IP地址作为该VLAN的网关，前提是设备存在该VLAN且有接口能传输该VLAN（接口不能Down）。

第六天

核心内容：DHCP动态地址分配、链路聚合、接入层安全（802.1X、端口隔离）

一、DHCP（动态主机配置协议）

作用：动态分配IP、掩码、网关、DNS等参数。

优点：简化终端配置、提升移动用户体验、提高地址利用率。

DHCP分配四步流程

  1. Discover：客户端广播寻找DHCP服务器。
  2. Offer：服务器单播回应Offer（包含IP等参数）。
  3. Request：客户端广播请求确认配置；续租也使用request包；分配相对固定地址。
  4. Ack：服务器单播确认分配，该IP不再分配他人。

终端获取地址后会发送免费ARP检查IP冲突（请求自己IP对应的MAC，无回应则正常使用）。

📌 一句话总结：DHCP通过Discover（广播找服务器）、Offer（单播回应IP参数）、Request（广播请求确认）、Ack（单播确认分配）四步动态分配IP/掩码/网关/DNS，终端获取地址后会发送免费ARP检查IP冲突。

二、链路聚合（Link Aggregation）

作用：提高带宽、增强可靠性、实现负载分担。

聚合分类

类型 特点
静态聚合 手工配置，不考虑对方状态（兼容性好）
动态聚合（LACP） 设备间通过LACP协商，自动检测错误，推荐使用（不同厂商对接可能失败）

华三动态模式默认均为 active（主动发送）。

📌 一句话总结：链路聚合将多条物理链路捆绑为一条逻辑链路，提高带宽、增强可靠性并实现负载分担；静态聚合手工配置（兼容性好），动态聚合通过LACP协议自动协商（推荐，但不同厂商对接可能失败）。

聚合要求

  1. 硬件一致（电口/光口、速率一致）。
  2. 软件一致（Access/Trunk、允许VLAN、PVID一致）。

    最佳实践：物理接口只加入聚合组，所有配置在聚合接口下完成。

📌 一句话总结：聚合要求硬件一致（电口/光口、速率相同）和软件一致（接口类型、允许VLAN、PVID相同），最佳实践是物理接口只加入聚合组，所有配置在聚合接口下完成；华三动态聚合失败时仍会选一个接口保证通信（其他厂商直接Down）。

二层静态聚合配置

[S1] interface Bridge-Aggregation 1
[S1] interface range GigabitEthernet 1/0/1 GigabitEthernet 1/0/2
[S1-if-range] port link-aggregation group 1

# 在聚合口下配置属性
[S1] interface Bridge-Aggregation 1
[S1-Bridge-Aggregation1] port link-type trunk
[S1-Bridge-Aggregation1] port trunk permit vlan all

二层动态聚合配置

[S1] interface Bridge-Aggregation 2
[S1-Bridge-Aggregation2] link-aggregation mode dynamic
[S1] interface range GigabitEthernet 1/0/7 GigabitEthernet 1/0/8
[S1-if-range] port link-aggregation group 2

注意：一边静态、一边动态无法正常聚合。华三动态聚合失败时，为保证通信，仍会选一个接口转发（其他厂商直接Down）。

查看聚合状态

[S1] display interface Bridge-Aggregation 1 brief
[S1] display link-aggregation summary

📌 一句话总结：display interface Bridge-Aggregation brief查看聚合接口状态，display link-aggregation summary查看聚合汇总信息。

三层路由器聚合配置

[R4] interface range GigabitEthernet 0/0 GigabitEthernet 0/1
[R4-if-range] port link-aggregation group 1

三、接入层安全技术

1. 802.1X认证

  • 原理：交换机配合认证服务器，终端未通过认证前内外网均无法访问。
  • 特点：安全性极高，但交换机需支持802.1X，成本较高。

📌 一句话总结：交换机配合认证服务器，终端未通过认证前内外网均无法访问，安全性极高但需要交换机支持802.1X功能（成本较高）。

2. 端口隔离

  • 原理：在同一广播域内，配置端口隔离后，主机间无法直接互访，可有效防止ARP欺骗等攻击。
  • 适用场景：同一广播域但无互访需求的终端。

📌 一句话总结：在同一个广播域内配置端口隔离后，主机间无法直接互访，能有效防止ARP欺骗等在同一广播域内发起的攻击。

第七天

核心内容：ACL（访问控制列表）与 NAT（网络地址转换）

一、ACL（访问控制列表）

ACL 的两大核心功能：匹配流量 与 访问控制。

1. 匹配流量（通配符掩码）

匹配依据为 五元组：源IP、目的IP、协议、源端口号（不常用，因为源端口是随机的）、目的端口号。

（1）基础匹配符

通配符掩码 含义 示例
0.0.0.255 匹配前24位固定，后8位任意 192.168.1.0 0.0.0.255 → 匹配 192.168.1.x 网段
0.0.255.255 匹配前16位固定，后16位任意 172.16.0.0 0.0.255.255 → 匹配 172.16.x.x
255.255.255.255 匹配任意地址 0.0.0.0 255.255.255.255 = any
0.0.0.0 精确匹配单个地址 192.168.1.10 0.0.0.0 → 仅匹配该主机

（2）范围匹配（难度二）

  • 192.168.1.32 0.0.0.31 → 匹配 192.168.1.32 ~ 192.168.1.63
  • 192.168.1.64 0.0.0.15 → 匹配 192.168.1.64 ~ 192.168.1.79
  • 192.168.1.128 0.0.0.63 → 匹配 192.168.1.128 ~ 192.168.1.191

（3）奇偶匹配（难度三）

观察二进制最后一位：1 为奇数，0 为偶数。通配符掩码 254（二进制 11111110）表示前7位任意，最后一位固定。

  • 192.168.1.100 0.0.254.255 → 匹配 192.168.1.x 中的奇数或偶数 IP（取决于 254 对应的数值奇偶性）。

（4）匹配地址类别

  • A类：0.0.0.0 127.255.255.255
  • B类：172.0.0.0 63.255.255.255
  • C类：192.0.0.0 31.255.255.255

（5）端口匹配操作符

  • eq — 等于（常用）
  • range — 范围
  • gt — 大于
  • lt — 小于

📌 一句话总结：ACL基于五元组（源/目的IP、协议、源/目的端口）匹配流量，使用通配符掩码（0表示必须匹配、1表示任意）灵活定义匹配范围，如0.0.0.255匹配前24位固定、后8位任意；范围匹配通过通配符掩码实现连续IP段匹配（如0.0.0.31匹配32个地址），奇偶匹配利用通配符掩码254控制二进制最后一位固定来实现奇/偶数IP的匹配。

2. ACL 分类与部署原则

类型 匹配依据 部署建议
基本ACL 仅源IP地址 离目的近
高级ACL 五元组 离源近（目的近亦可，但会增加无效转发）

万能法则：如果不会判断，统一放在目的近。

📌 一句话总结：基本ACL仅匹配源IP，建议部署在离目的近的位置；高级ACL匹配五元组，建议部署在离源近的位置（目的近亦可但会增加无效转发），不确定时统一放在目的近。

3. ACL 配置注意事项（重点）

  1. 自上而下匹配，命中即执行，不再继续向下 ⇒ 先小后大（精确条目放前面，大范围放后面）。

  2. ❌ 错误示例：先 permit 192.168.1.0/24，后 deny 192.168.1.10 → 后者永远不生效。

  3. 默认行为差异（华为/华三 vs 思科/锐捷）：

  4. 华为/华三：访问控制时默认允许；流量匹配时默认拒绝。
  5. 锐捷/思科：任何时候都默认拒绝。
  6. ✅ 建议：无论什么设备，都手工明确配置 permit any 或 deny any。

📌 一句话总结：ACL自上而下匹配（命中即执行，不再继续），需遵循"先小后大"原则（精确条目放前面）；华为/华三访问控制时默认允许、流量匹配时默认拒绝，思科/锐捷任何时候都默认拒绝，建议手工明确配置permit any或deny any。

4. 配置步骤

  1. 确定部署位置（根据上方原则判断源近或目的近）。
  2. 配置 ACL 规则（拒绝场景：deny xxx + permit any；仅允许场景：permit xxx + deny any）。
  3. 调用在接口的对应方向（in / out）。

5. 配置案例

案例1：基本ACL — PC5 不能访问 PC7

[R3] acl basic 2000
[R3-acl-ipv4-basic-2000] rule deny source 192.168.1.5 0.0.0.0
[R3-acl-ipv4-basic-2000] rule permit source any
[R3] interface GigabitEthernet 0/1
[R3-GigabitEthernet0/1] packet-filter 2000 outbound

案例2：基本ACL — 仅允许 PC5 访问 PC7

[R3] acl basic name onlypc5
[R3-acl-ipv4-basic-onlypc5] rule permit source 192.168.1.5 0
[R3-acl-ipv4-basic-onlypc5] rule deny source any
[R3] interface GigabitEthernet 0/0
[R3-GigabitEthernet0/0] packet-filter name onlypc5 inbound

⚠️ 注意：此配置如果调用在 inbound 方向，会拒绝 OSPF 等信息，可能导致邻居断开。推荐调用在 outbound 方向。

案例3：高级ACL — 拒绝 R1 Telnet R2

[R1] acl advanced 3000
[R1-acl-ipv4-adv-3000] rule deny tcp source 192.168.12.1 0 destination 192.168.12.2 0 destination-port eq telnet
[R1-acl-ipv4-adv-3000] rule permit ip

案例4：高级ACL — 仅允许 R3（192.168.23.3）Telnet R2

[R2] acl basic 2000
[R2-acl-ipv4-basic-2000] rule permit source 192.168.23.3 0
[R2-acl-ipv4-basic-2000] rule deny source any
[R2] telnet server acl 2000   # 调用位置不局限在物理接口

📌 一句话总结：基本ACL使用acl basic + rule deny/permit source控制源IP访问，高级ACL使用acl advanced + rule deny/permit tcp/ip控制五元组，通过packet-filter或telnet server acl调用在接口或服务上。

二、NAT（网络地址转换）

1. 产生背景

  • IPv4 地址不足，划分 私网地址 与 公网地址。
  • 私网地址范围：
  • A类：10.0.0.0 ~ 10.255.255.255
  • B类：172.16.0.0 ~ 172.31.255.255
  • C类：192.168.0.0 ~ 192.168.255.255
  • 私网地址访问公网前，必须转换为合法公网地址。

📌 一句话总结：由于IPv4地址不足，划分了私网地址（A类10.0.0.0/8、B类172.16.0.0/12、C类192.168.0.0/16）和公网地址，私网地址访问公网前必须转换为合法的公网地址。

2. NAT 分类

类型 方向 适用场景
SNAT（源地址转换） 内网 → 外网 所有网络都需要（临时分配公网地址）
DNAT（目的地址转换） 外网 → 内网 内网有对外提供服务的服务器时（固定映射）

📌 一句话总结：SNAT（源地址转换）用于内网访问外网，临时分配公网地址；DNAT（目的地址转换）用于外网访问内网的服务器，需要固定映射关系。

3. NAT 六种实现形式

① 静态 NAT

公网 IP 与私网 IP 一对一固定映射。支持 SNAT 和 DNAT，适用于重要业务服务器。

[R1] interface GigabitEthernet 0/1
[R1-GigabitEthernet0/1] nat static enable
[R1] nat static outbound 192.168.1.4 100.1.1.10

📌 一句话总结：公网IP与私网IP一对一固定映射，地址利用率低但支持SNAT和DNAT，适用于重要业务服务器。

② 动态 NAT

公网 IP 临时分配给私网主机，用完归还。同时在线人数 = 公网 IP 数量。仅支持 SNAT。

[R1] acl basic 2000
[R1-acl-ipv4-basic-2000] rule permit source 192.168.1.0 0.0.0.255
[R1] nat address-group 1
[R1-address-group-1] address 100.1.1.10 100.1.1.20
[R1] interface GigabitEthernet 0/1
[R1-GigabitEthernet0/1] nat outbound 2000 address-group 1 no-pat   # no-pat 不做端口转换

📌 一句话总结：公网IP临时分配给私网主机、用完归还，同时在线人数等于公网IP数量，仅支持SNAT。

③ NAPT（网络地址端口转换）⭐ 内网访问外网最常用

多个私网主机共享一个公网 IP，通过端口号区分。仅支持 SNAT。

[R1] interface GigabitEthernet 0/1
[R1-GigabitEthernet0/1] nat outbound 2000 address-group 1   # 省略 no-pat 即为 NAPT

📌 一句话总结：多个私网主机通过端口号共享一个公网IP，每个会话建立临时映射关系，是内网访问外网最常用的方式，仅支持SNAT。

④ Easy IP（华为/华三）

NAPT 的特例：直接将私网地址转换为出接口的公网地址。适用于无固定公网 IP 的场景（如 ADSL 拨号）。

[R1] acl basic 2000
[R1-acl-ipv4-basic-2000] rule permit source 192.168.1.0 0.0.0.255
[R1] interface GigabitEthernet 0/1
[R1-GigabitEthernet0/1] nat outbound 2000

📌 一句话总结：NAPT的特例，将私网地址直接转换为出接口的公网地址，适用于无固定公网IP的ADSL拨号场景。

⑤ 端口映射（NAT Server）⭐ 外网访问内网常用

固定将公网 IP:端口 映射到 私网 IP:端口（DNAT）。

[R1-GigabitEthernet0/1] nat server protocol tcp global 100.1.1.10 23 inside 192.168.1.7 23

📌 一句话总结：固定将公网IP:端口映射到私网IP:端口，用于外网主动访问内网服务器，属于DNAT。

⑥ NAT ALG（应用层网关）

针对 FTP 等包含随机端口信息的协议，ALG 可识别应用层数据并自动建立映射，解决普通 NAT 无法处理的问题。

📌 一句话总结：针对FTP等包含随机端口信息的协议，ALG可识别应用层数据中的私网IP和端口信息并自动建立映射，解决普通NAT无法处理此类协议的问题。

第八天

核心内容：网络注意事项、MVRP、Private VLAN、Super VLAN、QINQ、RSTP（快速生成树）

一、基础网络注意事项（承接前六天拓扑）

  1. 所有内网三层设备必须配置默认路由。
  2. 仔细检查 PC 的网关地址 是否配置错误。
  3. 外网路由器不能配置任何动态路由协议，本拓扑中所有公网地址段均视为直连。
  4. R8 的出口网段禁止宣告进 OSPF：
  5. ISP（运营商）不会与你建立 OSPF 邻居；
  6. OSPF 内部路由泄露给运营商存在严重安全风险。

📌 一句话总结：内网三层设备需配置默认路由、检查PC网关是否正确、外网路由器不能配置动态路由协议（公网地址段视为直连）、R8出口网段禁止宣告进OSPF（ISP不建立OSPF且存在安全风险）。

二、MVRP（VLAN 注册协议）

让中间交换机动态学习 VLAN 信息，无需手动逐个创建。

[S2] mvrp global enable                           # 全局开启
[S2] interface GigabitEthernet 1/0/2
[S2-GigabitEthernet1/0/2] mvrp enable             # 接口开启
[S2-GigabitEthernet1/0/2] mvrp registration normal # 模式（默认normal）

三种注册模式：

模式 行为
normal 可动态注册和注销（默认）
fixed 不接收新注册，也不注销已有
forbidden 已注册的 VLAN 信息也会被删除

📌 一句话总结：MVRP让中间交换机动态学习和注销VLAN信息，有三种模式——normal（动态注册/注销）、fixed（不接收新也不注销已有）、forbidden（已有VLAN信息也会消失）。

三、Private VLAN（私有VLAN）

在一个广播域内实现二层隔离，无需划分多个子网。

  • 主 VLAN（Primary）：与所有辅助 VLAN 通信。
  • 辅助 VLAN（Secondary）：
  • 团体 VLAN（Community）：可与主 VLAN 及同团体成员通信。
  • 隔离 VLAN（Isolated）：只能与主 VLAN 通信，互相隔离。

配置示例：

[S2] vlan 30
[S2] vlan 40
[S2] vlan 10
[S2-vlan10] private-vlan primary                      # 设置 vlan10 为主vlan
[S2-vlan10] private-vlan secondary 30 40              # 关联辅助vlan

[S2] interface GigabitEthernet 1/0/1
[S2-GigabitEthernet1/0/1] port access vlan 30
[S2-GigabitEthernet1/0/1] port private-vlan host      # 设为host端口（辅助vlan）

[S2] interface GigabitEthernet 1/0/2
[S2-GigabitEthernet1/0/2] port access vlan 40
[S2-GigabitEthernet1/0/2] port private-vlan host

[S2] interface GigabitEthernet 1/0/3
[S2-GigabitEthernet1/0/3] port access vlan 10
[S2-GigabitEthernet1/0/3] port private-vlan 10 promiscuous  # 设为混杂端口（主vlan）

📌 一句话总结：Private VLAN在一个广播域内实现二层隔离，主VLAN可与所有辅助VLAN通信，辅助VLAN分为团体VLAN（可同团体及主VLAN通信）和隔离VLAN（只能与主VLAN通信）。

四、Super VLAN（超级VLAN）

  • Sub VLAN（子VLAN）：实现二层隔离，物理接口划分，不能创建 VLANIF 接口。
  • Super VLAN（超级VLAN）：仅存在三层 VLANIF 接口，作为所有 Sub VLAN 的网关。
  • Sub VLAN 间互通需在 Super VLAN 的 VLANIF 上开启 ARP 代理。

📌 一句话总结：Super VLAN让所有Sub VLAN使用同一网段地址，Sub VLAN实现二层隔离且不能创建VLANIF接口，Super VLAN的VLANIF作为所有Sub VLAN的网关，Sub VLAN间互通需在Super VLAN上开启ARP代理。

五、QINQ（双层 VLAN 标签）

  • 内层标签：私网 VLAN，用于用户内部通信。
  • 外层标签：公网 VLAN，用于运营商骨干网传输。
  • 基本 QINQ：不管内层 VLAN 是多少，都打上相同的外层标签。
  • 灵活 QINQ：根据内层 VLAN 的不同，打上不同的外层标签。

📌 一句话总结：QINQ在数据帧上封装两层VLAN Tag，内层是私网VLAN（用户内部通信），外层是公网VLAN（运营商骨干网传输）；基本QINQ统一打相同外层标签，灵活QINQ根据内层VLAN不同打不同外层标签。

六、STP 与 RSTP（生成树协议）

1. STP 原有四大缺陷（收敛慢）

问题场景 收敛时间
PC 接入（未启用边缘端口） 30s
直连链路故障 30s
非直连链路故障 50s
初始化收敛 30s

📌 一句话总结：STP存在PC接入需30s、直连链路故障30s、非直连链路故障50s、初始化收敛30s四个收敛慢的问题。

2. RSTP 的六大改进点

改进①：端口状态精简（5 → 3）

RSTP 状态 对应 STP 状态
discarding（丢弃） disable / blocking / listening
learning（学习） learning
forwarding（转发） forwarding

📌 一句话总结：RSTP将STP的五种端口状态合并为discarding、learning、forwarding三种，机制更简约但收敛速度提升不明显。

改进②：新增端口角色（解决直连故障 30s）

  • 替代端口（Alternate）：收到其他交换机发来的更优 BPDU，是根端口的备份。
  • 备份端口（Backup）：收到本交换机发来的更优 BPDU，是指定端口的备份（不常见）。
  • 边缘端口：连接终端，直接进入转发状态。

替代端口在初始化时即确定无环备用路径，直连故障时可立即切换。

📌 一句话总结：RSTP新增替代端口（根端口的备份，收到其他交换机更优BPDU）和备份端口（指定端口的备份，收到本交换机更优BPDU），在初始化时即确定无环备用路径，直连故障时可立即切换。

改进③：P/A 机制（Proposal / Agreement）— 解决初始化 30s

  • 在 STP 运算基础上增加 P/A 回应机制，收到 A 置位后立即转发。
  • 将初始化收敛时间缩短至 1s 以内。

📌 一句话总结：RSTP在STP运算基础上增加P/A回应机制，收到A置位后立即转发，将初始化收敛时间缩短至1秒以内。

改进④：次优 BPDU 处理机制 — 解决非直连故障 50s

  • 非直连故障时，替代端口收到次优 BPDU → 转为指定端口（DP），反向发送最优 BPDU。
  • 原交换机收到最优 BPDU → 选举为根端口（RP）→ 回应 A 置位 → 快速转发。

📌 一句话总结：非直连故障时，替代端口收到次优BPDU后转为指定端口并反向发送最优BPDU，原交换机收到后选举为根端口并回应A置位快速转发，解决非直连故障50s问题。

改进⑤：边缘端口特性

  • 接入终端直接进入转发（0s 等待）。
  • 边缘端口收到 BPDU 后，立即丧失边缘特性，变为普通端口。
  • 不参与 P/A 拥塞，状态变化不发送 TC BPDU，TC BPDU 不会清除边缘端口的 MAC 表。
  • ⚠️ 注意：边缘端口依然会发送 BPDU，若两个边缘端口互接，可能形成临时环路（0~2s）。

📌 一句话总结：边缘端口接入终端直接进入转发（0s等待），收到BPDU后立即丧失边缘特性变为普通端口；不参与P/A拥塞、不发送TC BPDU、TC BPDU不清除其MAC表，但两边缘端口互接可能形成0~2s临时环路。

改进⑥：TC BPDU 传递优化

STP RSTP
需先发送 TCN 通知根桥，由根桥发出 TC BPDU 变化节点直接发出 TC BPDU，无需等待根桥

📌 一句话总结：STP中TC BPDU需先发送TCN通知根桥、由根桥发出，而RSTP中变化节点可直接发出TC BPDU，无需等待根桥。

第九天

核心内容：STP/RSTP缺点、PVSTP、MSTP（多生成树协议）、STP保护机制、VRRP（虚拟路由冗余协议）

一、STP / RSTP 的缺点

STP和RSTP在整个网络中只能运行一棵生成树，存在以下问题：

  1. 拥塞端口只有一个：冗余链路中只有一条被阻塞，不转发任何数据，造成带宽资源浪费。
  2. 无法实现负载分担：所有VLAN的流量都走同一棵生成树，无法根据VLAN将流量分配到不同链路上。

📌 一句话总结：STP和RSTP全网只有一棵生成树，拥塞端口不转发任何数据造成带宽浪费，且无法实现多VLAN间的负载分担。

二、PVSTP（每VLAN生成树协议）

全称：Per-VLAN Spanning Tree Protocol（思科私有协议）

核心思想

  • 一个VLAN一棵生成树，不同VLAN拥有独立的生成树拓扑。
  • 将不同VLAN的根桥放在不同交换机上，使不同VLAN的拥塞端口落在不同链路上，从而实现线路负载分担。

缺点

  • VLAN数量多时，生成树的数量也相应增多，对交换机的CPU和内存消耗极大。

📌 一句话总结：PVSTP为每个VLAN单独运行一棵生成树，通过将不同VLAN的根桥放在不同交换机上实现负载分担，但VLAN数量多时会严重消耗交换机资源。

三、MSTP（多生成树协议）

全称：Multiple Spanning Tree Protocol（IEEE 802.1s标准协议，华为/华三设备默认运行）

1. MSTP的核心优势

  • 通过实例（Instance） 控制生成树的数量，从而控制对交换机资源的消耗。
  • 通过控制每个实例的根桥位置，实现不同实例间的负载分担。
  • 完全继承RSTP的所有优点（P/A机制、边缘端口、替代/备份端口等）。

📌 一句话总结：MSTP通过实例控制生成树数量来降低资源消耗，并通过控制各实例根桥位置实现负载分担，同时继承了RSTP的所有快速收敛特性。

2. MSTP域（Region）

当交换机数量较大时，可以划分多个MSTP域，减轻设备运算压力，加快收敛速度。

判断交换机是否在同一个域的条件（三者必须完全一致）：

  1. 域名（Region Name）相同（华三设备域名默认是设备的MAC地址，必须手动修改才能一致）
  2. 修订号（Revision Level）相同（默认均为0，无实际意义，保持一致即可）
  3. 实例与VLAN的映射关系（Instance ↔ VLAN）相同（有一个默认的实例0）

📌 一句话总结：MSTP可以划分多个域来减轻设备压力，判断是否在同一域需满足三个条件——域名相同、修订号相同、实例与VLAN的映射关系相同。

3. IST 与 CST

概念 全称 作用范围 生成树数量
IST Internal Spanning Tree（内部生成树） 运行在MSTP域内 可运行多棵生成树（每个实例一棵）
CST Common Spanning Tree（公共生成树） 运行在MSTP域之间 只能运行一棵生成树

关键结论：通过MSTP实现负载均衡，只能在域内完成（因为域间只有一棵CST，无法负载分担）。

多域场景下新增端口角色：

  • Master端口：域内交换机连接域外交换机时，负责域间通信的端口。
  • 域边缘端口：位于MSTP域边界，连接其他域的端口。

📌 一句话总结：MSTP域内运行IST（可多棵生成树，实现负载分担），域间运行CST（只有一棵生成树，无法负载分担）；多域场景下新增Master端口和域边缘端口。

① 切换生成树模式为MSTP（设备默认即为MSTP模式，此命令通常无需执行）

bash

[S1] stp mode mstp

② 创建VLAN并配置Trunk（准备工作）

bash

[S4] vlan 4

四、STP保护机制

1. BPDU保护（BPDU Protection）

  • 作用对象：边缘端口。
  • 原理：边缘端口本应只连接终端设备，不应收到BPDU。如果边缘端口收到了BPDU，说明有人私接了交换机，存在环路风险。BPDU保护是一种更严格的惩罚措施——直接关闭（shutdown）该接口。
  • 恢复方式：需管理员手动恢复（或在配置error-down auto-recovery后自动恢复）。

bash

[S2] stp bpdu-protection                   # 全局开启BPDU保护（对设备上所有边缘端口生效）

📌 一句话总结：BPDU保护作用于边缘端口，若边缘端口收到BPDU则直接关闭该接口，防止因私接交换机引发环路，是一种更严格的惩罚措施。

2. 根桥保护（Root Protection）

  • 作用对象：指定端口（只能在指定接口下配置）。
  • 问题场景：新加入的交换机优先级更高，会抢占根桥身份，导致整个生成树拓扑重新计算，拥塞端口位置改变，网络震荡。
  • 原理：在指定端口上启用根保护后，如果该接口收到更优的BPDU（意味着有新的交换机想成为根桥），会立即将该接口拥塞（discarding） 。
  • 恢复方式：如果一段时间内没有收到更优BPDU，接口可自主恢复转发状态。

bash

[S2] interface GigabitEthernet 1/0/3
[S2-GigabitEthernet1/0/3] stp root-protection   # 在指定接口下开启根保护

📌 一句话总结：根桥保护作用于指定端口，当收到更优BPDU时立即拥塞该接口防止根桥被抢占，无更优BPDU后可自主恢复转发。

3. 环路保护（Loop Protection）

  • 使用频率：很少使用。
  • 问题场景：接口因单向链路故障等原因无法收到BPDU（但线路物理状态仍为UP） ，交换机会误以为拓扑变化，将原先拥塞的接口恢复转发，从而引发环路。
  • 原理：启用环路保护后，如果接口长时间收不到BPDU，则将接口状态强制设置为discarding（丢弃） ，防止环路产生。

bash

[S2] interface GigabitEthernet 1/0/4
[S2-GigabitEthernet1/0/4] stp loop-protection

📌 一句话总结：环路保护用于解决接口因无法收到BPDU（但线路仍UP）而误恢复转发引发环路的问题，启用后收不到BPDU时将接口强制设为discarding状态，使用较少。

4. TC BPDU保护（TC Protection）

  • 问题场景：黑客模拟TC BPDU不断发送给交换机，导致交换机频繁删除MAC地址表，网络性能严重下降（TC BPDU攻击）。
  • 原理：开启TC BPDU保护后，交换机在单位时间内（默认为10秒）只处理一次TC BPDU，超出次数的TC BPDU将被忽略，从而保护设备CPU和MAC表稳定。

bash

[S2] stp tc-protection                    # 开启TC BPDU保护

📌 一句话总结：TC BPDU保护防止黑客通过大量发送TC BPDU导致交换机频繁删除MAC表，开启后在10秒内只处理一次TC BPDU，超出次数的被忽略。

[S1] stp mode stp                         # 切换为STP模式

六、VRRP（虚拟路由冗余协议）

全称：Virtual Router Redundancy Protocol（虚拟路由冗余协议）

1. VRRP的产生背景与核心思想

  • 解决的问题：网关单点故障。如果网络中只有一个网关，该设备故障后，所有依赖该网关的主机都将断网。
  • 核心思想：多台设备共同维持一个虚拟IP地址，使用该虚拟IP作为主机的网关。其中一台设备作为Master负责转发，其他作为Backup实时监控Master状态。如果Master故障，Backup自动接替，保证网关不中断。
  • 部署方式：VRRP是基于接口的（通常配置在VLANIF接口或三层物理接口上）。

📌 一句话总结：VRRP通过多台设备共同维护一个虚拟IP作为网关来解决网关单点故障，Master负责转发，Backup监控Master状态并在其故障时自动接替，部署时基于接口配置。

2. VRRP的角色

角色 职责
Master 负责所有数据转发，定期（每1秒）发送VRRP通告报文给Backup
Backup 监视Master的状态，如果连续3秒没有收到Master的通告报文，则认为Master故障，主动切换为Master

📌 一句话总结：Master负责转发并每1秒发送VRRP通告（心跳包），Backup监控通告报文，3秒未收到则主动切换为Master。

3. VRRP角色选举规则

比较顺序（先比1，相同则比2）：

  1. 优先级（Priority） ：越大越优
  2. 默认值：100
  3. 取值范围：0 ~ 255（配置范围为 1 ~ 254）
  4. 0：表示放弃Master资格（立即从选举中退出）
  5. 255：表示接口的物理IP地址与虚拟IP地址相同（即该设备同时拥有虚拟IP，自动成为Master）
  6. 接口IP地址：越大越优（仅当优先级相同时比较）

状态切换特点：

  • 只有优先级为 255 的设备，端口角色可以直接从 init 变为 master。
  • 其他设备都是先进入 backup 状态，在规定时间内没有收到比自己优先级更高的Master通告后，再切换为 master。

📌 一句话总结：VRRP选举先比优先级（默认100，1-254可配置，255为IP地址拥有者自动Master，0表示退出选举），相同则比接口IP地址（越大越优）；只有优先级255能直接成为Master，其他设备先进入Backup状态再根据通告情况升级。

4. VRRP基础配置命令

① 配置VRRP（在VLANIF接口下）

bash

[S2] interface Vlan-interface 5
[S2-Vlan-interface5] vrrp vrid 5 virtual-ip 192.168.5.1
# 配置VRRP组编号为5（双方必须一致），虚拟IP地址为192.168.5.1（即主机的网关地址）

② 查看VRRP状态

bash

[S2] display vrrp                        # 查看VRRP简要状态
[S2] display vrrp verbose                # 查看VRRP详细信息

③ 调整VRRP通告时间

bash

[S2-Vlan-interface5] vrrp vrid 5 timer advertise 50
# 修改VRRP通告报文发送间隔（单位：厘秒，默认100厘秒=1秒）
# 时间越短，Backup感知Master故障越快
# 注意：主设备修改后，备设备会自动同步；但锐捷设备时间不一致则无法组建VRRP

④ 调整优先级（确定主备）

bash

[S2-Vlan-interface5] vrrp vrid 5 priority 120
# 调整优先级为120（默认100），数值越高越优先成为Master

📌 一句话总结：VRRP基础配置使用vrrp vrid X virtual-ip配置虚拟IP，用display vrrp查看状态，通过vrrp vrid X priority调整优先级确定主备，通告时间可通过vrrp vrid X timer advertise调整（主设备调整后备设备自动同步）。

5. VRRP特殊场景与解决方案

场景①：上行链路追踪（上行链路故障切换）

问题： VRRP主备切换的判断标准是Backup能否收到Master的VRRP通告报文。但如果Master的上行链路（连接外网的链路）发生故障，下行链路仍然正常，Master仍然可以正常发送VRRP通告，Backup不会切换。此时Master虽然VRRP状态正常，但实际上无法访问外网，导致所有流量中断。

解决方案： 配置上行链路追踪（Track） ，将VRRP优先级与上行链路状态绑定。如果上行链路故障，VRRP优先级自动降低（降低后的优先级低于Backup），从而触发Backup切换为Master。

前提条件：必须开启抢占模式（设备默认开启），否则优先级降低后Backup也不会抢占。

bash

[S2] track 1 interface GigabitEthernet 1/0/2
# 设置追踪项1，监控GigabitEthernet 1/0/2接口状态

[S2] interface Vlan-interface 5
[S2-Vlan-interface5] vrrp vrid 5 track 1 priority reduced 30
# 如果追踪项1（上行接口）故障，该设备的VRRP优先级自动减30
# 例如：原优先级120 → 故障后变为90，低于Backup的100，触发切换

📌 一句话总结：上行链路追踪用于解决Master上行链路故障但VRRP通告正常导致无法切换的问题，通过track将VRRP优先级与上行接口状态绑定，上行故障时自动降低优先级触发切换（需开启抢占）。

场景②：抢占时延（防止频繁切换丢包）

问题： Master故障恢复后，如果立即抢占回Master角色，此时设备的路由表、ARP表等信息可能尚未完全收敛，在这段时间内转发的数据可能被丢弃，造成业务中断。

解决方案： 配置抢占时延（Preempt Delay） ，Master故障恢复后，等待一段时间（如120秒）再抢占回Master角色，确保路由表和转发表完全收敛。

注意：只能在主设备（Master）上配置。

bash

[S2-Vlan-interface5] vrrp vrid 5 preempt-mode delay 12000
# 配置抢占时延为12000厘秒 = 120秒
# Master故障恢复后，等待120秒再抢占回Master角色

📌 一句话总结：抢占时延防止Master故障恢复后立即抢占导致路由表未收敛而丢包，配置后Master恢复需等待指定时间（如120秒）再抢占，只能在主设备上配置。

场景③：负载分担（多VRRP组互为主备）

问题： 在传统的VRRP部署中，Backup设备不进行数据转发，完全处于闲置状态，造成资源浪费。

解决方案： 配置多个VRRP组，在不同的VRRP组中互为主备。例如：

  • VRRP组1：S2为Master，S3为Backup
  • VRRP组2：S3为Master，S2为Backup

将不同VLAN的主机网关分别指向不同VRRP组的虚拟IP，实现负载分担。

📌 一句话总结：通过配置多个VRRP组并互为主备（如组1设备A主B备、组2设备B主A备），将不同VLAN网关指向不同VRRP组，实现设备间的负载分担，避免Backup设备闲置浪费资源。

场景④：VRRP + MSTP 联动

问题： VRRP的Master和MSTP的根桥必须在同一台设备上。如果VRRP Master在交换机A，而MSTP根桥在交换机B，流量路径可能出现次优路径（数据绕路），影响转发效率。

解决方案： 在部署时，确保VRRP Master的设备和对应VLAN的MSTP根桥为同一台设备。具体做法是：

  • 将VRRP Master的优先级和该VLAN对应MSTP实例的根桥设置在相同的交换机上。
  • 通常结合MSTP多实例和VRRP多组一起部署，实现VLAN级别的路径最优 + 负载分担。

📌 一句话总结：VRRP的Master必须和对应VLAN的MSTP根桥在同一台设备上，否则可能出现次优路径导致数据绕行，影响转发效率，需结合MSTP多实例和VRRP多组统一规划。

6. VRRP认证（增强安全性）

bash

[S2-Vlan-interface5] vrrp vrid 5 authentication-mode md5 plain shangwen
# 配置VRRP认证，使用MD5加密，密码为shangwen
# 防止非法设备加入VRRP组，增强安全性

第十天

核心内容：IRF（智能弹性架构）堆叠、M-LAG（跨设备链路聚合）

一、IRF（堆叠）

全称：Intelligent Resilient Framework（智能弹性架构），华三/华为的堆叠技术（华为称为CSS/iStack）

1. IRF的核心思想

IRF可以将多台物理设备从逻辑上虚拟成一台设备，在管理和转发层面都表现为单一设备。

  • 管理员只需登录一台设备即可管理整个堆叠系统。
  • 流量在堆叠成员之间可以跨设备转发。

📌 一句话总结：IRF将多台物理设备虚拟成一台逻辑设备，统一管理、统一转发，简化网络架构。

2. IRF的角色

角色 职责
Master（主设备） 负责管理整个IRF系统的配置信息，同步给所有Slave；同时参与数据转发
Slave（从设备） 配置信息从Master同步而来，也参与数据转发，当Master故障时自动接替

📌 一句话总结：IRF中Master管理整个系统的配置并参与转发，Slave同步配置并参与转发，Master故障时Slave自动接替。

3. 堆叠连接方式

设备之间通过堆叠线进行连接：

  • 可以使用专用堆叠线（如SFP+堆叠电缆）
  • 也可以使用网线或光纤（通过万兆端口）

堆叠拓扑推荐：环形拓扑（可靠性高于链形，一条链路故障不影响堆叠系统运行）。

📌 一句话总结：堆叠设备之间通过专用堆叠线或光纤/网线连接，推荐使用环形拓扑以提升可靠性。

4. 堆叠线的作用

  1. 维持堆叠系统运作：传输堆叠协议报文，维护IRF成员状态。
  2. 设备间数据转发：跨设备的流量通过堆叠线转发。

📌 一句话总结：堆叠线同时承载堆叠协议报文（维持系统运作）和跨设备数据转发。

5. IRF vs VRRP+MSTP 对比

对比项 IRF堆叠 VRRP + MSTP
管理复杂度 简单（统一管理） 复杂（需分别管理多设备）
切换速度 毫秒级（ms） 秒级（s）
网络性能 稍高（无协议开销） 稍低（有VRRP/MSTP协议开销）
通用性 差——需同厂商、同系列、同软件版本 强——不需要同厂商，不严格要求同型号
软件升级 麻烦（需整体升级） 便利（可逐台升级）

📌 一句话总结：IRF管理简单、切换快（ms）、性能高，但要求同厂商同型号同版本且升级麻烦；VRRP+MSTP通用性强、升级便利，但管理复杂、切换慢（s）。

6. IRF配置命令

① 第一台设备（Master）配置

bash

[S1] irf domain 1                                    # 创建IRF域，域名为1
[S1] irf member 1 priority 32                        # 调整本设备优先级为32（越高越优先成为Master）

# 将物理接口加入堆叠口（必须先关闭接口）
[S1] interface range Ten-GigabitEthernet 1/0/50 Ten-GigabitEthernet 1/0/51
[S1-if-range] shutdown                                # 只有接口关闭才能加入堆叠口

[S1] irf-port 1/1                                    # 创建堆叠口1/1（成员1的堆叠口1）
[S1-irf-port1/1] port group interface Ten-GigabitEthernet 1/0/50   # 将物理接口加入堆叠口
[S1] irf-port 1/2                                    # 创建堆叠口1/2（成员1的堆叠口2）
[S1-irf-port1/2] port group interface Ten-GigabitEthernet 1/0/51

[S1] interface range Ten-GigabitEthernet 1/0/50 Ten-GigabitEthernet 1/0/51
[S1-if-range] undo shutdown                           # 重新打开接口

[S1] save                                             # ⚠️ 必须保存！从设备加入IRF会自动重启
[S1] irf-port-configuration active                    # 激活IRF端口配置

② 第二台设备（Slave）配置

bash

[H3C] irf member 1 renumber 2                        # ⚠️ 关键步骤：将成员编号从1改为2（默认都是1，冲突）
# 配置完成后，保存重启生效。重启后接口编号变为 2/0/1

[H3C] irf domain 1                                   # 域名必须与Master一致

[H3C] interface range Ten-GigabitEthernet 2/0/50 Ten-GigabitEthernet 2/0/51
[H3C-if-range] shutdown

[H3C] irf-port 2/1
[H3C-irf-port2/1] port group interface Ten-GigabitEthernet 2/0/51
[H3C] irf-port 2/2
[H3C-irf-port2/2] port group interface Ten-GigabitEthernet 2/0/50    # ⚠️ 注意与对方保持交叉连接

[H3C] interface range Ten-GigabitEthernet 2/0/50 Ten-GigabitEthernet 2/0/51
[H3C-if-range] undo shutdown

[H3C] save
[H3C] irf-port-configuration active

关键配置要点：

  • 两台设备编号不能冲突（默认都是1，需修改一台为2）。
  • 堆叠口连接需交叉（设备1的irf-port1接设备2的irf-port2，设备1的irf-port2接设备2的irf-port1）。
  • 必须先保存再激活，否则从设备重启后配置丢失。

📌 一句话总结：IRF配置需修改成员编号避免冲突、配置堆叠口并交叉连接、保存配置后激活；堆叠口操作前必须先shutdown物理接口，完成后undo shutdown。

二、MAD（多Active检测）

全称：Multi-Active Detection（多主检测）

1. MAD的产生背景

问题场景：IRF堆叠系统发生分裂（如堆叠线缆全部断开），原来的一个堆叠系统会变成两个独立的IRF系统，且两个系统中都有Master设备，都认为自己是合法的，导致IP地址冲突、网络震荡。

📌 一句话总结：IRF分裂后会出现两个独立的Master设备，导致IP地址冲突和网络震荡，MAD用于检测并处理这种分裂场景。

2. MAD的检测机制

MAD检测后，会在两个分裂的IRF系统中选择一个继续存活（Active），另一个迁移为 Recovery（恢复） 状态。处于Recovery状态的IRF系统，除保留口外，其余所有接口全部关闭，从而避免冲突。

3. MAD的检测方式

检测方式 原理 是否需要额外线路 限制
LACP检测 通过跨IRF成员的LACP聚合链路，检测对方的Domain ID和Active ID 不需要 必须使用华三设备（LACP扩展字段非标准）
ARP检测 通过ARP报文携带MAD信息进行检测 不需要 —
ND检测 通过IPv6 ND报文携带MAD信息进行检测 不需要 —
BFD检测 BFD会话UP则说明IRF已分裂 需要额外线路（独立的BFD链路） 不需要华三设备（通用性强）

判定逻辑：如果Domain ID相同，但Active ID不同，则认为IRF已分裂。

📌 一句话总结：MAD通过LACP/ARP/ND（不需要额外线路，但LACP仅限华三设备）或BFD（需额外线路，通用性强）检测IRF分裂，发现分裂后将其中一个系统设为Recovery状态并关闭其所有业务接口。

三、M-LAG（跨设备链路聚合）

全称：Multi-Chassis Link Aggregation（跨设备链路聚合），华三称为M-LAG，华为称为E-Trunk，思科称为vPC

1. M-LAG的核心思想

M-LAG将两台独立的物理设备通过peer-link链路连接，在逻辑上表现为一台设备，实现跨设备的链路聚合。下游设备（如服务器或交换机）通过聚合口同时连接两台设备，实现设备级冗余。

📌 一句话总结：M-LAG通过peer-link连接两台独立设备，使下游设备可以通过跨设备链路聚合实现设备级冗余，解决了VRRP中备设备闲置和IRF分裂风险大的问题。

2. M-LAG的三个核心概念

概念 说明
peer-link链路 两台M-LAG设备之间的连接链路，用于维持M-LAG系统运行，必要时转发用户数据（通常使用聚合接口）
keepalive链路 检测M-LAG分裂问题，但无法维持M-LAG系统运行（只做检测，不做同步）
M-LAG组 一组跨设备的聚合接口（每台设备上一个聚合口，两者组成一个M-LAG组）

📌 一句话总结：M-LAG三大核心——peer-link维持系统运行并转发跨设备数据，keepalive仅检测分裂（不维持系统），M-LAG组由两台设备上的聚合接口共同组成。

3. M-LAG流量转发原则

原则①：单向隔离

从peer-link链路接收到的广播/组播/未知单播流量，不会再发送给M-LAG接口。这样可以防止同一条广播流量从peer-link和M-LAG接口同时到达下游设备，避免重复接收广播流量。

📌 一句话总结：单向隔离——从peer-link收到的广播流量不再发送给M-LAG接口，防止下游设备收到重复广播。

原则②：本地优先转发

本设备能直接转发的流量，优先从本设备转发，不会绕行peer-link链路，从而节省peer-link带宽，降低延迟。

📌 一句话总结：本地优先转发——能从本设备直接转发的流量不走peer-link绕行，节省带宽、降低延迟。

4. M-LAG vs IRF 对比

对比项 M-LAG IRF
分裂风险 小（分裂后各自独立运行，有MAD检测） 大（堆叠分裂影响面广）
升级方式 可逐台升级（一台升级时另一台承担流量） 需整体升级，麻烦
设备要求 不严格要求同型号（但建议同厂商） 需同厂商、同系列、同版本
管理方式 分别管理两台设备 统一管理

📌 一句话总结：M-LAG相比IRF分裂风险更小、支持逐台升级，设备要求更灵活，但管理上仍为独立设备。

第十一天

核心内容：Monitor Link（接口联动）、BFD（双向转发检测）、NQA（网络质量分析）

一、Monitor Link（接口联动）

作用：实现接口联动，提高上下行设备的切换速度。

Monitor Link将上行接口和下行接口绑定，当上行接口故障时，自动将下行接口关闭；上行接口恢复时，自动重新打开下行接口，从而触发下游设备快速切换路径。

📌 一句话总结：Monitor Link通过上下行接口联动，上行故障时自动关闭下行接口，触发下游设备快速切换，提高收敛速度。

二、BFD（双向转发检测）

全称：Bidirectional Forwarding Detection（双向转发检测）

1. BFD的核心特点

  • 协议无关：可以与OSPF、IS-IS、BGP、静态路由等多种协议联动。
  • 链路无关：支持各种类型的链路（以太网、MPLS、POS等）。
  • 检测机制：采用简单的 Hello机制，在规定时间内没有收到对端的BFD报文，则判定链路故障，立即通知上层协议触发切换。
  • 收敛速度：可达毫秒级（ms），远快于协议自身的收敛时间（OSPF默认40秒）。

📌 一句话总结：BFD是一种与协议和链路无关的高速检测机制，通过毫秒级Hello报文快速检测链路故障并通知上层协议触发切换。

2. BFD的重要机制

① BFD无邻居发现机制

BFD本身不会主动发现邻居，必须依赖上层协议（如OSPF）指导完成会话建立。流程：上层协议先通过Hello发现并建立邻居 → BFD再与对应的邻居建立BFD会话。

📌 一句话总结：BFD无邻居发现能力，必须依赖上层协议（如OSPF）先建立邻居后，BFD再与之建立会话。

② BFD检测特性

  • 支持多跳也支持单跳：单跳是不跨广播域（直连），多跳是跨广播域（非直连）。
  • 支持回声功能（Echo） ：对端设备不支持BFD或对端不是自己的设备时，本端发送BFD回声报文，对端直接环回，由本端自行检测链路状态。

📌 一句话总结：BFD支持单跳和多跳检测；回声功能允许本端发送报文、对端环回，由本端自行检测，适用于对端不支持BFD的场景。

3. BFD联动配置命令

① BFD联动OSPF（接口下开启）

bash

[R1-GigabitEthernet0/0] ospf bfd enable                    # 接口下开启BFD联动OSPF
[R1-GigabitEthernet0/0] bfd min-receive-interval 100       # 配置BFD接收间隔（毫秒）
[R1-GigabitEthernet0/0] bfd min-transmit-interval 100      # 配置BFD发送间隔（毫秒）
[R1-GigabitEthernet0/0] bfd detect-multiplier 3            # 配置检测倍数（3×100ms=300ms检测到故障）

bash

③ BFD回声功能配置

[R1-GigabitEthernet0/0] bfd min-echo-receive-interval 100

📌 一句话总结：BFD配置需在接口下开启与上层协议的联动（如ospf bfd enable），设置发送/接收间隔和检测倍数；回声功能需配置echo-source-ip；静态路由可通过bfd control-packet参数联动。

三、NQA（网络质量分析）

全称：Network Quality Analyzer（网络质量分析）

1. NQA与BFD的区别

对比项 BFD NQA
检测能力 仅检测链路通断（Up/Down） 能检测网络质量（延迟、抖动、丢包率）以及服务状态（HTTP/FTP/DNS是否可用）
配置方式 需两端配置 只需一端配置探测信息，对端只需要能回应探测协议（ICMP/TCP/UDP服务开启即可）
依赖性 协议无关 依赖于相关协议（ICMP/TCP/UDP等）

2. NQA的特点

  • 不需要对端设备专门配置NQA，对端只需支持并开启相关服务（如ICMP ping响应、TCP端口监听、UDP服务等）。
  • 可主动探测网络路径的延迟、抖动、丢包率，还可探测服务可用性（如HTTP 200状态码、DNS解析是否成功）。

📌 一句话总结：NQA相比BFD不仅能检测链路通断，还能检测网络质量（延迟/抖动/丢包）和服务状态（HTTP/DNS等），且只需一端配置探测参数，对端只需正常回应探测协议即可。

第十二天

核心内容：组播（完整版）、AAA认证授权计费、端口安全控制、园区网维护、路由聚合、OSPF补充

一、组播

1. 组播的特点

优点：

  • 节约带宽：相比单播（给N个主机发N份），组播只发送一份数据，网络带宽占用少。
  • 减轻服务器压力：服务器只需发送一份数据，无需为每个接收者单独复制。
  • 可跨广播域：相比广播（只能在同一个广播域内），组播可以跨路由器转发。
  • 精准发送：只发送给加入特定组播组的成员，通信效率高。
  • 适用于一对多的流量场景。

缺点：

  • 组播只能基于 UDP 进行数据发送，继承了UDP的不可靠性，可能出现丢包、乱序等问题。

📌 一句话总结：组播节约带宽、减轻服务器压力、可跨广播域且精准发送，适用于一对多场景，但只能基于UDP，存在丢包和乱序风险。

2. 组播地址

组播IP地址范围：224.0.0.0 ~ 239.255.255.255

永久组地址（知名组播地址） ：224.0.0.0 ~ 224.0.1.255

  • 224.0.0.1 → 所有节点
  • 224.0.0.2 → 所有路由器
  • 224.0.0.5 → OSPF路由器
  • 224.0.0.6 → OSPF DR/BDR
  • 224.0.0.18 → VRRP

组播MAC地址：

  • 固定前缀：01-00-5E
  • 只有 23个位 可变（组播IP地址有28个位可变）
  • 结果：32个组播IP地址映射到同一个组播MAC地址（存在MAC地址冲突风险）

📌 一句话总结：组播IP范围为224.0.0.0~239.255.255.255，其中224.0.0.0~224.0.1.255为知名组播地址（如224.0.0.5为OSPF、224.0.0.18为VRRP）；组播MAC地址固定以01-00-5E开头，因MAC只有23位可变而IP有28位可变，导致32个组播IP映射到同一个组播MAC。

3. 组播协议体系

组播涉及三个层面的协议：

层面 协议 作用
主机-路由器之间 IGMP（Internet组管理协议） 主机告知路由器自己想加入或离开哪个组播组
路由器-路由器之间 PIM（协议无关组播） 构建组播分发树，确定流量转发路径
二层交换机 IGMP Snooping 交换机侦听IGMP报文，建立组播MAC表避免泛洪

二、IGMP（主机到路由器的协议）

全称：Internet Group Management Protocol（互联网组管理协议） 作用：让主机告知路由器，自己需要哪个组播组的流量。整体机制是路由器查询，主机响应。

1. IGMPv1

两种报文：

  • 普遍组查询：路由器每隔 60秒 发送一次普遍组查询，查询广播域内是否存在组成员。
  • 主机报告：（1）响应路由器的查询报告；（2）主机加入某组播组时会主动发送报告。

特殊机制：

  • 报告抑制：如果本广播域内有多台主机加入了同一个组播组，其中一台设备报告后，其他主机收到这个报告就不再重复发送了。
  • 默不作声的离开：主机离开组播组时，不会告知路由器。路由器是通过三次查询都没有得到响应后，才知道主机已离开，才停止发送组播流量。

📌 一句话总结：IGMPv1有普遍组查询和主机报告两种报文，通过报告抑制减少重复流量，但主机离组时不会通知路由器，需三次查询无响应后才停止转发。

2. IGMPv2（最常用）

四种报文：

  • 普遍组查询：路由器周期性查询该网段有哪些组播组成员。
  • 主机报告：主机回应路由器，报告自己加入的组播组。
  • 主机离组：主机主动离开组播组时通知路由器。
  • 特定组查询：路由器收到离组信息后，只查询特定组是否还有成员。

离组机制：

  1. 主机离开组播组时，主动向路由器发送离组信息。
  2. 路由器收到后，每1秒发送一次特定组查询（共发2次），查询该组是否还有组成员。
  3. 两次查询都没有收到主机报告 → 认为没有组成员 → 停止发送该组播流量。

📌 一句话总结：IGMPv2新增了主机离组和特定组查询两种报文，离组后路由器通过两次特定组查询（每秒一次）确认无成员后停止转发组播流量，解决了v1"默不作声离开"的问题。

3. IGMPv3

核心改进：增加了组播源的选择能力——SSM（特定源组播）。

IGMP版本 工作模式 特点
IGMPv1/v2 ASM（任意源组播） 主机只指定组地址，不关心组播源是谁
IGMPv3 SSM（特定源组播） 主机同时指定组地址和组播源地址，可拒绝或接受特定源的流量

📌 一句话总结：IGMPv1/v2工作在ASM（任意源组播，主机只指定组地址），IGMPv3工作在SSM（特定源组播，主机可指定组播源地址），SSM尚未普及。

4. IGMP Snooping（侦听）

问题： 交换机依赖MAC地址表进行转发，但MAC地址表不会自动学习组播MAC地址（组播MAC地址01-00-5E开头不会作为源MAC出现）。结果：所有组播流量在二层被泛洪转发——不管主机是否想接收，全部都会收到。

解决方案：交换机运行 IGMP Snooping，通过侦听路由器与主机之间的IGMP报文，自动学习并建立组播MAC地址表。

工作原理：

  1. 交换机收到 普遍组查询 的接口 → 标记为 路由器接口。
  2. 交换机收到 主机报告 的接口 → 标记为 主机接口。
  3. 根据报告中的组播IP地址，自动计算组播MAC地址，生成MAC地址表项。
  4. 组播流量只向有成员的接口转发，不再泛洪。

组播MAC地址计算：前25位固定，后23位取组播IP地址的后23位。

📌 一句话总结：IGMP Snooping让交换机通过侦听IGMP报文自动建立组播MAC地址表（组播MAC前25位固定、后23位取自组播IP），使组播流量只转发给有成员的接口，避免二层泛洪。

三、PIM（路由器到路由器的协议）

全称：Protocol Independent Multicast（协议无关组播） 作用：构建组播分发树，确定组播流量的出接口。

1. 组播分发树与组播路由表

组播路由器之间运行PIM协议，构建组播分发树，形成组播路由表。

组播路由表格式 {S, G}：

  • S = 组播源IP地址
  • G = 组播组地址

路由表关键字段：

字段 说明
IIF（入接口） 从哪个接口接收组播流量。只能有1个
OIFlist（出接口列表） 向哪些接口转发组播流量。可以有多个

组播流量在网络中每个链路只出现一份，因此每个设备只能有一个入接口。

📌 一句话总结：组播路由器构建分发树形成组播路由表{S,G}，其中IIF（入接口）只能有一个（组播流量每链路只出现一份），OIFlist（出接口列表）可以有多个。

2. RPF（反向路径转发）—— 确定入接口

当一台组播路由器从多个接口都收到了同一份组播流量时，需要确定哪个接口作为入接口。

判断依据：查找单播路由表，去往该组播源（S）的出接口，就是组播的入接口（IIF）。只有从RPF接口收到的组播流量才被转发，其他接口收到的相同流量被丢弃。

📌 一句话总结：RPF通过查询单播路由表确定去往组播源的出接口作为组播入接口（IIF），从非RPF接口收到的组播流量将被丢弃，防止环路。

3. PIM-DM（密集模式）

核心逻辑：模拟所有广播域都有接收者。

工作机制：

  • 默认情况下，除入接口外的所有接口都是出接口，全部转发组播流量。
  • 如果某个网段没有接收者，该网段的路由器会发送剪枝（Prune） 消息，逐级剪掉不需要的枝条。

关键动作：

  • 泛洪：每隔一段时间会将组播流量泛洪到整个网络。
  • 剪枝：如果不需要组播流量，向上级发送剪枝，将对应接口从出接口列表移除。
  • 剪枝的场景：（1）RPF失败的接口；（2）末端路由器没有收到对应IGMP报告；（3）中间路由器所有出接口都被剪枝，则继续向上发送剪枝；（4）断言失败的设备。
  • 嫁接：之前被剪枝过的接口如果重新需要组播流量，可以发送嫁接消息，一直嫁接到有组播流量的设备。

模式比喻："推"的模式——先全部推过去，不需要的再剪掉。

适用场景：接收者密集的小型网络。

分发树：采用 SPT（源树） 。

📌 一句话总结：PIM-DM采用"推"模式（先全部泛洪再剪枝），关键动作包括泛洪、剪枝（RPF失败/无IGMP报告/无出接口/断言失败）和嫁接，使用SPT源树，适用于接收者密集的小型网络。

4. PIM-SM（稀疏模式）

核心逻辑：模拟没有任何接收者。

工作机制：

  • 路由器默认不转发任何组播流量。
  • 只有接收者主动发送 加入（Join） 消息后，沿途路由器才将对应接口加入OIFlist，流量才开始转发。

模式比喻："拉"的模式——有需要的人自己来拉取。

适用场景：接收者分散的大型网络（如互联网）。

分发树：采用 RPT（共享树） 。

运作机制（四步） ：

第1步：选择RP点（汇聚点）

  • 方式一：静态手工配置（所有设备都要手工配置，RP点故障需要全部切换）
  • 方式二：BSR（自举路由器协议），自动选择RP点位置。多个CRP（候选RP），每个CRP有自己的服务范围，通过BSR选举出真正的RP。

第2步：接收者到RP的树建立

  • PC发送IGMP报告给路由器，路由器收到后向RP点发送Join消息，沿途建立 （*，G） 表项。

第3步：组播源到RP的树建立

  • 组播源发送组播信息给组播路由器，路由器将组播信息封装成单播的注册信息发送给RP。
  • RP收到注册信息后查看是否存在接收者：
  • 没有接收者 → 回应注册暂停，不建立树。
  • 有接收者 → 回应注册保留，建立树。
  • RP点向组播源发送Join消息，沿途建立 （S，G） 表项。

第4步：RPT向SPT的切换

  • 当组播流量达到阈值时，需要从RPT切换到SPT。
  • 接收者的路由器直接向组播源发送Join消息，沿途建立 （S，G） 表项。
  • 切换完成后，剪枝原本RP点的 （*，G） 表项。

📌 一句话总结：PIM-SM采用"拉"模式，通过RP点（静态或BSR选举）构建RPT共享树，接收者发Join建立（*,G）、源端发注册消息建立（S,G），流量达到阈值后从RPT切换到SPT源树，适用于接收者分散的大型网络。

5. SPT（源树）vs RPT（共享树）

对比项 SPT（源树） RPT（共享树）
建立方式 组播源直接到接收者之间建立 在网络中选择一个RP点，源和接收者都找RP
优点 路径最优（最短路径） 建立的树少（节省设备资源）
缺点 要为每个组播源都建立单独的树，数量大 路径不一定是最优，RP点是单点故障
使用协议 PIM-DM默认使用；PIM-SM在切换后使用 PIM-SM默认使用

📌 一句话总结：SPT源树路径最优但数量大，PIM-DM默认使用；RPT共享树节省资源但路径不一定最优且RP是单点故障，PIM-SM默认使用，流量达到阈值后从RPT切换为SPT。

四、AAA（认证、授权、计费）

全称：Authentication、Authorization、Accounting

1. AAA的作用

AAA是一种网络安全框架，提供三个核心功能：

  • 认证（Authentication） ：确认用户身份是否合法。
  • 授权（Authorization） ：确定合法用户可以访问哪些资源、执行哪些操作。
  • 计费（Accounting） ：记录用户的操作行为，便于审计和计费。

2. AAA的应用场景

场景 常用协议 说明
远程管理设备（管理员登录交换机/路由器） TACACS+ 支持认证、授权、计费三个功能分离，更安全
用户认证（如802.1X接入认证） RADIUS 支持认证和计费，没有单独的授权报文（授权与认证合并）

📌 一句话总结：AAA提供认证、授权、计费三功能，远程管理设备常用TACACS+（三功能分离），用户接入认证常用RADIUS（认证+计费，无单独授权）。

五、端口安全控制

目的：防止非法用户随意接入网络。

1. 802.1X认证

  • 原理：交换机配合认证服务器（如RADIUS），终端未通过认证前内外网均无法访问。
  • 特点：安全性极高，但需要交换机支持802.1X功能，成本较高。

2. MAC认证

  • 原理：只有MAC地址在白名单中的设备才允许接入网络。
  • 特点：配置简单，但MAC地址容易被仿冒，安全性相对较低。

3. 端口安全

  • 原理：交换机端口自动学习并记录MAC地址，只有安全MAC（被允许的MAC） 才能通过该端口通信。
  • 特点：可限制端口上允许的MAC地址数量，超出限制则触发惩罚动作（如关闭端口）。

📌 一句话总结：端口安全控制包括802.1X认证（配合服务器、安全性高）、MAC认证（白名单、配置简单但易仿冒）和端口安全（自动学习安全MAC、可限制数量），防止非法用户接入。

六、园区网维护

1. SNMP（简单网络管理协议）

作用：帮助管理员了解网络中设备的运行状态（CPU、内存、接口流量等）。

架构：SNMP服务器端 + 各网络设备客户端。服务器定期查询客户端信息并统一展示；客户端出现告警时主动发送给服务器。

版本 特点
SNMPv1 基本功能：查询/响应、设置、告警。通过团体名作为身份认证（明文，不安全）
SNMPv2c 提高了查询效率，仍使用团体名认证
SNMPv3 增加了加密和认证机制，安全性大幅提升

📌 一句话总结：SNMP让管理员集中监控网络设备状态（CPU/内存/流量），v1和v2c用团体名认证（明文不安全），v3增加加密认证安全性最高。

2. Telemetry（远程遥测协议）

  • 新一代设备状态监控协议。
  • 相比SNMP，速度更快（采用订阅方式，设备主动推送数据，无需轮询）。
  • 支持高频率数据采集，实时性更强。

📌 一句话总结：Telemetry是新一代监控协议，采用订阅推送方式替代SNMP轮询，速度更快、实时性更强。

3. LLDP（链路层发现协议）

  • 作用：发现直连设备的相关信息（IP地址、功能、软件版本等），帮助自动发现整网拓扑。
  • 安全建议：不使用的时候推荐关闭，因为存在信息泄露风险。

📌 一句话总结：LLDP用于发现直连设备信息辅助拓扑发现，不使用时应关闭以防信息泄露。

4. 流量镜像技术

  • 作用：将一个接口的流量复制一份给另一个接口，主要用于流量监控（如IDS/IPS分析）。
  • 本地流量镜像：源接口和目的接口都在同一台设备上。
  • 远程流量镜像：源接口和目的接口不在同一台设备上，需要设置一个镜像VLAN来传输镜像流量。

📌 一句话总结：流量镜像将接口流量复制一份用于监控分析，源和目的同设备为本地镜像，跨设备为远程镜像（需镜像VLAN）。

5. NTP（网络时间协议）

  • 作用：在网络中设置NTP服务器，所有设备同步该服务器的时间，保证全网时间统一。
  • 重要性：日志审计、证书验证、协议运行（如OSPF）都需要统一时间。

📌 一句话总结：NTP让网络设备统一同步时间，确保日志审计、协议运行和证书验证的时间一致性。

七、路由聚合

1. 路由聚合的优点

  • 减小路由表：多个子网路由合并为一条汇总路由，节省设备内存。
  • 减少路由更新流量：路由协议传递的条目减少，节约带宽。
  • 减少更新带来的网络波动：某条子网链路震荡时，不会触发整网路由更新，只影响聚合路由内部。

📌 一句话总结：路由聚合减小路由表、减少更新流量、抑制局部网络波动影响范围。

2. 路由聚合分类

类型 说明 推荐度
自动聚合 将路由聚合成主类掩码（A类/8、B类/16、C类/24） 不推荐（不支持不连续子网）
手工聚合 管理员手工设定聚合后的掩码 推荐

3. 路由聚合引发的环路及解决方案

问题：聚合路由可能包含不存在的子网，当数据包访问这些不存在的子网时，可能会被路由到聚合路由的始发设备，而始发设备又通过默认路由或聚合路由再次转发，形成路由环路。

解决方案：在聚合路由的始发设备上，自动产生一条汇总路由指向null0（空接口） ，匹配到不存在的子网时直接丢弃，防止环路。

📌 一句话总结：路由聚合需手工配置（推荐），为防止聚合后访问不存在子网引发环路，设备会在始发者上自动生成一条指向null0的汇总路由丢弃匹配流量。

4. CIDR 与 VLSM

概念 全称 作用 方向
CIDR 无类别域间路由 将多个子网路由聚合成一个大的网段 聚合（合）
VLSM 可变长子网掩码 将一个大的网段划分成多个小的子网 划分（分）

📌 一句话总结：CIDR是"合"（多个子网聚合成一个大网段），VLSM是"分"（一个大网段划分成多个子网），两者方向相反，VLSM是为了节省IP地址。

八、OSPF补充

1. OSPF区域

划分区域的目的：减轻设备运算压力，每台路由器只需维护自己所属区域的完整链路状态信息。

区域规则：

  • Area 0（骨干区域） ：核心区域，实现区域间路由信息交互。
  • 非骨干区域：所有非骨干区域都必须与骨干区域直接相连。

特殊角色：

  • ABR（区域边界路由器） ：连接两个及以上区域，其中一个必须是Area 0。
  • ASBR（自治系统边界路由器） ：连接两个不同的路由协议（如OSPF和RIP），需要配置路由引入。

📌 一句话总结：OSPF划分区域减轻设备压力，所有非骨干区域必须直连Area 0；ABR连接区域（其一为Area 0），ASBR连接不同路由协议并需配置路由引入。

2. OSPF网络类型

OSPF网络类型是为了解决数据链路层兼容性问题。网络类型不是必须调整，但调整后会让OSPF在网络中运作更优（如PPP链路不选DR更好）。

网络类型 默认封装 是否选DR/BDR Hello/Dead 邻居发现
Broadcast（广播型） 以太网 需要 10s / 40s 自动
P2P（点到点型） PPP 不需要 10s / 40s 自动
NBMA（非广播多路访问） 帧中继（已淘汰） 需要 30s / 120s 手工建立
P2MP（点到多点型） 无默认封装 不需要 30s / 120s 自动
Loopback Loopback接口 — — —

特殊说明：

  • Loopback接口不管配置什么掩码，发出的路由都是32位主机路由。

重要注意事项：

  • 一边是Broadcast一边是P2P：能建立邻居，但不能正常学习路由（DR选举机制不一致）。
  • 一边是P2MP一边是P2P：不能建立邻居，调整hello时间一致后可以建立邻居和学习路由。
  • 结论：网络类型只是运作机制不同，并不直接影响邻居建立和路由学习。影响邻居建立的核心因素是 Hello/Dead时间，影响路由学习的核心因素是 是否需要DR/BDR。

手工调整网络类型：

bash

[R2-GigabitEthernet0/1] ospf network-type p2p
# 在只有两台设备的链路上，可手工调整为P2P类型，加快收敛并避免无意义的DR选举

NBMA手工建立邻居：

bash

[R1] ospf 1
[R1-ospf-1] peer 192.168.12.2
# NBMA网络需要手工指定邻居IP地址

📌 一句话总结：OSPF网络类型因底层封装而异——Broadcast（以太网，选DR）、P2P（PPP，不选DR）、NBMA（帧中继，选DR且需手工建邻居）、P2MP（不选DR）；Loopback接口路由固定为32位；调整网络类型时需确保Hello时间和DR选举机制两端一致。

第十三天

核心内容：OSPF协议详解（报文类型、邻居状态机、邻居建立排障、LSA更新机制、LSA六种分类详解、路由引入、虚链路）

一、OSPF五种报文

报文类型 全称 作用
Hello Hello包 发现、建立并维持邻居关系。通过组播 224.0.0.5 发送
DBD Database Description（链路状态数据库描述） 描述本设备的LSDB摘要，用于邻居间数据库同步
LSR Link State Request（链路状态请求） 向邻居请求缺少的LSA
LSU Link State Update（链路状态更新） 发送LSA更新信息（携带完整的LSA）
LSACK Link State Acknowledgment（链路状态确认） 对收到的LSU进行确认，保证可靠传输

Hello包建立邻居的关键参数：router-id、area、认证、hello/dead、掩码、option

📌 一句话总结：OSPF五种报文各司其职——Hello发现维护邻居、DBD描述数据库摘要、LSR请求缺失LSA、LSU发送更新、LSACK确认保证可靠性，其中Hello通过224.0.0.5组播发送。

二、OSPF邻居状态机

状态 说明
DOWN 关闭状态，未收到任何Hello包
INIT 收到了Hello包，但Hello包中没有收到自身的router-id
2-way 收到了Hello包，且Hello包中存在自身的router-id → 邻居关系建立。在广播和NBMA网络中，只与DR/BDR进行下一步
Exstart 交换DBD的序列号，确定主从关系（主设备先发送DBD）
Exchange 交换DBD报文（描述LSDB摘要）
Loading 交换LSR和LSU（请求和接收完整的LSA）
FULL 收到LSACK，完成LSDB同步 → 邻接关系建立

特殊状态：

  • Attempt：只出现在 NBMA 网络中，表示正在单向手工建立邻居（NBMA无法自动发现邻居）。

📌 一句话总结：OSPF邻居经历DOWN→INIT→2-way（邻居建立，广播网只与DR/BDR继续）→Exstart（选主从）→Exchange→Loading→FULL（邻接建立），NBMA特有Attempt状态。

三、OSPF邻居无法建立的十大原因

1. 子网掩码不匹配

现象：收到Hello包，但因参数不匹配不认可，邻居表为空。

排查命令：

bash

<R1> display ospf statistics error          # 查看OSPF错误统计
<R1> terminal debugging                      # 显示debug信息
<R1> debugging ospf packet hello             # 抓取OSPF Hello信息
<R1> undo debugging all                      # 关闭所有debug

📌 一句话总结：掩码不匹配时路由器会收到Hello包但不认可，邻居表为空，可通过display ospf statistics error或debugging ospf packet hello排查。

2. Router-ID冲突

场景 结果
直连 无法建立邻居
不直连 可以建立邻居，但会产生路由震荡
在不同区域 可以建立邻居，也可以正常学习路由（每台路由器只维护自己区域的信息）

提示信息（两分钟一次，易被忽略）：

text

% OSPF 1 Duplicate router ID 10.1.1.1 on interface GigabitEthernet0/0, sourced from IP address 192.168.12.1.

📌 一句话总结：Router-ID冲突直连无法建邻居，不直连可建但路由震荡，不同区域可正常建邻——结论是OSPF Router-ID只要本区域不冲突即可。

3. Area-ID不匹配

报错提示：一端提示错误的area-id，另一端提示错误的虚链路。

📌 一句话总结：Area-ID不匹配会导致邻居建立失败，报错信息分别提示区域ID错误和虚链路错误。

4. 认证类型不匹配

OSPF认证分为：

  • 明文认证（simple） 和 MD5认证。
  • 区域认证 和 接口认证（按影响范围分）。

bash

[R1-GigabitEthernet0/0] ospf authentication-mode simple plain shangwen
# 配置接口下的明文认证

bash

[R2] ospf 1
[R2-ospf-1] area 0
[R2-ospf-1-area-0.0.0.0] authentication-mode md5 1 plain shangwen@123
# 配置区域下的MD5认证，keyid和密钥需一致

优先级：接口认证 > 区域认证

📌 一句话总结：OSPF认证分明文和MD5两种，按范围分接口认证和区域认证，接口认证优先级高于区域认证，双方认证类型必须一致。

5. 认证密码不匹配

📌 一句话总结：认证类型相同但密码不同也会导致邻居建立失败。

6. Hello/Dead时间不匹配

bash

[R1-GigabitEthernet0/0] ospf timer hello 5
# 调整hello时间，dead时间会自动调整为hello的4倍

📌 一句话总结：Hello时间不匹配导致无法建邻居，调整hello后dead自动适配，dead也可单独调整。

7. Option不匹配

📌 一句话总结：Option字段（如特殊区域标记）不一致会导致邻居建立失败。

8. Attempt状态——NBMA单向邻居

NBMA网络需要手工建立邻居。

bash

[R1] ospf 1
[R1-ospf-1] peer 192.168.12.2
# NBMA网络手工指定邻居

📌 一句话总结：NBMA网络因无法自动发现邻居，需手工配置peer，此时会出现Attempt状态。

9. 邻居卡在2-way——DR选举失败

原因：广播域内所有路由器的OSPF优先级都为0，无法选出DR。

bash

[R1-GigabitEthernet0/0] ospf dr-priority 0
# 优先级为0表示不参与DR选举

📌 一句话总结：广播域内所有设备优先级均为0时无法选出DR，邻居将一直卡在2-way状态（因为只有DR/BDR才继续交换）。

10. MTU不匹配

bash

[R1-GigabitEthernet0/0] mtu 1400
[R1-GigabitEthernet0/0] ospf mtu-enable
# 华三设备默认不检查MTU，开启MTU检查后才会校验

现象：邻居状态卡在 Exstart 状态（DBD报文无法交换）。

📌 一句话总结：MTU不匹配时邻居卡在Exstart状态，华三默认不检查MTU，需用ospf mtu-enable开启检查。

五、OSPF LSA六种分类详解

1. 区域内LSA

（1）Router LSA（1类LSA）

  • 谁发的：每台路由器都会为自己所属区域产生一条
  • 干什么用：描述自身的拓扑信息和路由信息
  • 传播范围：本区域内传播

不同网络类型的表现：

  • P2P网络：几个邻居就有几个拓扑信息，几个直连网段就有几个路由信息
  • 广播型网络（Broadcast） ：广播域内不管几个路由器都只有一个拓扑信息（DR），中间互连网段不需要1类LSA描述

（2）Network LSA（2类LSA）

  • 谁发的：由该广播域的 DR 发出
  • 干什么用：描述本广播域的拓扑信息和路由信息
  • 传播范围：本区域内传播

📌 一句话总结：1类LSA每台路由器每个区域发一条描述自身拓扑和路由，P2P邻居数即拓扑数、广播域只有DR一个拓扑；2类LSA由DR发出描述广播域拓扑和路由，均在区域内传播。

2. 区域间LSA

（3）Summary-Network LSA（3类LSA）

  • 谁发的：由起始区域的ABR产生，后续区域的ABR重新生成（ABR转发时重新封装）
  • 干什么用：描述区域间的路由信息
  • 传播范围：在除了本区域之外的所有其他区域传递

特点：一条路由对应一个3类LSA，描述的是去往这个目标网络要找哪个ABR的router-id。

📌 一句话总结：3类LSA由ABR产生并逐跳重生，一条路由一个LSA，描述去往目标网段需经过的ABR，在除本区域外的所有区域传递。

3. 外部路由LSA

（4）Summary-ASBR LSA（4类LSA）

  • 谁发的：由ASBR所属区域的ABR产生，后续区域的ABR重新生成
  • 干什么用：描述如何到达ASBR的router-id
  • 传播范围：在除了ASBR所属区域之外的所有其他区域传递

📌 一句话总结：4类LSA由ASBR所在区域的ABR产生并逐跳重生，描述去往ASBR的路径，在除ASBR所在区域外的所有区域传递。

（5）AS-External LSA（5类LSA）

  • 谁发的：由 ASBR 产生
  • 干什么用：描述外部路由信息
  • 传播范围：在整个OSPF网络中传播（泛洪到所有区域）

外部路由类型：

类型 度量值计算 特点
Type 1（一类） 内部开销 + 外部开销 更精确，随内部路径变化而变化
Type 2（二类） 只计算外部开销（默认） 不随内部路径变化

bash

[R6-ospf-1] import-route rip allow-direct type 1
# 将RIP路由引入OSPF，并修改为Type 1

📌 一句话总结：5类LSA由ASBR产生在整个OSPF域泛洪，描述外部路由；默认Type 2只算外部开销，Type 1为内+外开销更精确。

4. 路由引入配置

bash

[R6] rip 1
[R6-rip-1] version 2
[R6-rip-1] undo summary                     # 取消自动汇总
[R6-rip-1] network 192.168.67.0             # 宣告RIP网段

[R6] ospf 1
[R6-ospf-1] import-route rip                # 将RIP路由引入OSPF（5类LSA）

[R6] rip 1
[R6-rip-1] import-route ospf 1 allow-direct  # 将OSPF路由引入RIP
# allow-direct：引入路由时同时包含直连路由

路由引入要点：

  • 在中间设备（同时运行两个协议）上配置
  • 路由引入是单向的（需双向引入才能实现互访）
  • 默认只引入路由表中的该协议路由，不含直连，需加 allow-direct 参数

📌 一句话总结：路由引入在边界设备上配置且为单向，需双向分别配置才能互访，默认只引入协议路由不含直连，加allow-direct可一并引入直连路由。

六、虚链路（Virtual Link）

1. 虚链路的使用场景

场景 说明
不连续的骨干区域 Area 0被非骨干区域隔断，通过虚链路逻辑上恢复连续性
没有和骨干区域相连的非骨干区域 非骨干区域没有直连Area 0，通过虚链路逻辑上接入骨干
备份路径 防止不连续的骨干区域，可作为冗余备份

2. 虚链路的限制

  • 虚链路只能跨越一个区域（不能跨越多个区域）
  • 可以连续启用多个虚链路，但不推荐

3. 虚链路配置

bash

[R4] ospf 1
[R4-ospf-1] area 1                    # 中间穿越区域
[R4-ospf-1-area-0.0.0.1] vlink-peer 10.6.6.6   # 对端路由器的router-id

📌 一句话总结：虚链路用于解决不连续骨干区域或非骨干未连骨干的问题，只能跨越一个区域、可多跳但不推荐，通过vlink-peer指定对端router-id配置。

七、OSPF路由优先级顺序

路由类型 符号 优先级顺序
区域内路由 O_INTRA 最高（1）
区域间路由 O_INTER 次高（2）
外部路由Type 1 O_ASE1 第三（3）
外部路由Type 2 O_ASE2 最低（4）

顺序：OSPF区域内 > OSPF区域间 > OSPF外部路由一类 > OSPF外部路由二类

📌 一句话总结：OSPF路由优先级从高到低为：区域内（O_INTRA）> 区域间（O_INTER）> 外部一类（O_ASE1）> 外部二类（O_ASE2）。

第十四天

核心内容：OSPF特殊区域（Stub/Totally Stub/NSSA/Totally NSSA）、OSPF路由聚合、OSPF安全机制（认证/静默端口/路由过滤）

一、OSPF特殊区域

1. 特殊区域的产生背景

OSPF划分区域之后，路由器只维护自己区域的拓扑信息，但仍然要维护所有的路由信息。对于末端路由器来说，路由表的规模仍然很大，压力依然存在。

特殊区域的核心思想：拒绝某些LSA进入本区域，从而减小路由表，用一条默认路由取代所有被拒绝的外部/区域间路由信息。

配置限制：特殊区域只能配置在末端区域（Area 0 和虚链路穿越的区域不能配置特殊区域）。

📌 一句话总结：OSPF特殊区域通过拒绝部分LSA进入末端区域来减小路由表，用一条默认路由取代所有外部/区域间路由，但只能配置在非骨干且无虚链路的末端区域。

2. Stub区域（末节区域）

拒绝的LSA：4类、5类LSA（外部路由）

允许的LSA：1类、2类、3类LSA

默认路由：由 ABR自动产生 一条默认路由（3类LSA），用于访问外部网络。

功能丧失：Stub区域不能引入外部路由（不能连接外部网络）。

配置要求：本区域所有路由器（包括ABR）都必须配置 stub。

配置命令：

bash

[R3] ospf 1
[R3-ospf-1] area 1
[R3-ospf-1-area-0.0.0.1] stub
# 区域内所有路由器都需要配置

📌 一句话总结：Stub区域拒绝4/5类LSA（外部路由），ABR自动生成默认路由替代，区域内所有路由器均需配置stub，且丧失引入外部路由功能。

3. Totally Stub区域（完全末节区域）

拒绝的LSA：3类、4类、5类LSA（区域间路由 + 外部路由全部拒绝）

允许的LSA：1类、2类LSA

默认路由：由 ABR自动产生 一条默认路由（3类LSA），用于访问区域外所有网络。

功能丧失：完全Stub区域不能引入外部路由。

配置要求：

  • 本区域所有路由器配置 stub
  • ABR 上额外增加 no-summary 参数

配置命令：

bash

[R3] ospf 1
[R3-ospf-1] area 1
[R3-ospf-1-area-0.0.0.1] stub no-summary
# 只在ABR上添加no-summary，其他路由器只配置stub即可

📌 一句话总结：Totally Stub在Stub基础上进一步拒绝3类LSA（区域间路由），ABR加no-summary参数后生成默认路由替代所有区域外路由，区域内只保留1/2类LSA。

4. NSSA区域（次末节区域）

全称：Not-So-Stubby Area

拒绝的LSA：4类、5类LSA（外部路由不能从外部进入）

特殊能力：本区域引入的外部路由可以以 7类LSA 的方式在本区域内传递。即NSSA区域是唯一一个能产生自己外部路由的特殊区域。

7类LSA特点：

  • 由NSSA区域的 ASBR 产生
  • 只在 NSSA区域内部 传递
  • 一旦传出NSSA区域，恢复为5类LSA 的身份

默认路由：NSSA区域是唯一不会自动产生默认路由的特殊区域，需要在ABR上手工配置 default-route-advertise。

配置命令：

bash

[R3] ospf 1
[R3-ospf-1] area 1
[R3-ospf-1-area-0.0.0.1] nssa default-route-advertise   # ABR上需加此参数
# 其他设备只配置 nssa 即可

bash

[R4] ospf 1
[R4-ospf-1] area 1
[R4-ospf-1-area-0.0.0.1] nssa
# 非ABR设备只配置nssa

📌 一句话总结：NSSA拒绝4/5类LSA进入，但允许本区域ASBR产生7类LSA引入外部路由（仅在NSSA内传递，传出恢复为5类），且是唯一不自动产生默认路由的特殊区域，需在ABR手工指定default-route-advertise。

5. Totally NSSA区域（完全次末节区域）

拒绝的LSA：3类、4类、5类LSA（区域间路由 + 外部路由全部拒绝）

特殊能力：本区域引入的外部路由仍可以以 7类LSA 进入。

默认路由：由 ABR自动产生 一条默认路由。

配置命令：

bash

[R3] ospf 1
[R3-ospf-1] area 1
[R3-ospf-1-area-0.0.0.1] nssa no-summary
# ABR上添加no-summary

bash

[R4] ospf 1
[R4-ospf-1] area 1
[R4-ospf-1-area-0.0.0.1] nssa
# 非ABR设备只配置nssa

📌 一句话总结：Totally NSSA在NSSA基础上增加拒绝3类LSA，ABR加no-summary后自动生成默认路由，既支持本区域引入外部路由（7类LSA）又减少路由条目。

6. 四种特殊区域对比总结

区域类型 拒绝的LSA 默认路由 能否引入外部路由 配置要点
Stub 4、5类 ABR自动生成 ❌ 不能 所有路由器配置 stub
Totally Stub 3、4、5类 ABR自动生成 ❌ 不能 ABR加 no-summary
NSSA 4、5类（从外进入） 不自动生成，需手工 ✅ 能（7类LSA） ABR加 default-route-advertise
Totally NSSA 3、4、5类（从外进入） ABR自动生成 ✅ 能（7类LSA） ABR加 no-summary

二、OSPF路由聚合

OSPF只能在区域间和外部路由两个位置实现路由聚合。

1. 区域间路由聚合（ABR上配置）

配置位置：只能在 ABR 上进行配置。

配置命令：

bash

[R3] ospf 1
[R3-ospf-1] area 0                              # 要汇总的路由条目所在的区域
[R3-ospf-1-area-0.0.0.0] abr-summary 10.2.2.0 255.255.254.0
# 将区域0中的路由聚合为10.2.2.0/23

2. 外部路由聚合（ASBR上配置）

配置位置：只能在 ASBR 上配置。

配置命令：

bash

[R2] ospf 1
[R2-ospf-1] asbr-summary 10.1.0.0 255.255.252.0
# 将引入的外部路由聚合为10.1.0.0/22

3. 防环机制

配置OSPF汇总后，设备会自动产生一条指向null0的汇总路由，用于防止路由环路。

📌 一句话总结：OSPF路由聚合分两种——ABR上使用abr-summary聚合区域间路由，ASBR上使用asbr-summary聚合外部路由，配置后自动生成指向null0的防环路由。

三、OSPF安全机制

1. 认证

OSPF支持明文认证和MD5认证，按影响范围分为接口认证和区域认证。

bash

# 接口明文认证
[R1-GigabitEthernet0/0] ospf authentication-mode simple plain shangwen

# 区域MD5认证
[R2] ospf 1
[R2-ospf-1] area 0
[R2-ospf-1-area-0.0.0.0] authentication-mode md5 1 plain shangwen@123

📌 一句话总结：OSPF认证分明文和MD5两种，可配置在接口级或区域级，接口认证优先级高于区域认证。

2. 静默端口（Silent-Interface）

功能：配置静默端口后，该接口只发布网段信息，不建立OSPF邻居，不发送Hello包。

适用场景：

  • 连接PC的接口（无需建立OSPF邻居）
  • 保证网络安全，只允许特定接口建立OSPF邻居

配置命令：

bash

[R1] ospf 1
[R1-ospf-1] silent-interface GigabitEthernet 0/0
# 将G0/0设为静默端口，只发布网段，不建立邻居

bash

[R1] ospf 1
[R1-ospf-1] silent-interface all
[R1-ospf-1] undo silent-interface GigabitEthernet 0/0
# 除G0/0外所有接口均不建立OSPF邻居

📌 一句话总结：静默端口只发布网段信息但不建立OSPF邻居（不发送Hello），常用于连接终端的接口，也可通过silent-interface all+undo实现白名单效果。

3. 路由过滤（Filter-Policy）

目标：实现IT部门不能访问财务部门，可以从两个层面实现：

层面 实现方式 效果
转发平面 使用ACL拒绝IT访问财务 路由表不变，在数据转发时拦截
控制平面 使用Filter-Policy过滤路由 IT路由器学习不到财务路由，路由表不存在则自动丢弃

OSPF Filter-Policy的局限性：

  • Import方向：可以生效——不影响LSA进入，但阻止该LSA生成路由表
  • Export方向：对3类LSA无效，对5类LSA有效（且只能在ASBR上配置）

核心原理：Filter-Policy无法过滤LSA本身，只是阻止LSA在本设备生成路由表。如果后续还有其他路由器，仍然可以收到被过滤的路由信息。

配置命令：

bash

[R2] acl basic 2000
[R2-acl-ipv4-basic-2000] rule deny source 10.1.2.1 0.0.0.0
[R2-acl-ipv4-basic-2000] rule permit source any

[R2] ospf 1
[R2-ospf-1] filter-policy 2000 import
# 阻止10.1.2.1对应的LSA生成路由表

不同LSA在Filter-Policy Export方向的效果：

LSA类型 Export方向是否生效 生效位置
3类LSA ❌ 不生效 —
5类LSA ✅ 生效 只能在ASBR上配置

📌 一句话总结：Filter-Policy在Import方向阻止LSA生成路由表（但不阻止LSA进入）；在Export方向对3类LSA无效、对5类LSA有效（仅ASBR）；本质是控制平面过滤，被过滤路由后续路由器仍可能收到。

五、ISIS协议

全称：Intermediate System to Intermediate System（中间系统到中间系统协议）

1. ISIS与OSPF的宏观对比

对比项 ISIS OSPF
协议起源 为OSI模型中的CLNP协议提供服务，后兼容IP协议 专门为TCP/IP协议栈设计
兼容性 兼容性很好，天然支持多种网络层协议 仅支持IP协议
适用场景 更适合扁平化的运营商网络 更适合灵活多变的园区网
区域划分 基于设备（整台设备属于一个区域） 基于接口（不同接口可在不同区域）
层次结构 Level 1（非骨干）/ Level 2（骨干）/ Level 1-2（边界） Area 0（骨干）/ 非骨干区域
网络层 基于数据链路层（直接封装在二层帧中） 基于网络层（封装在IP包中，协议号89）
网络类型 只有点到点和广播型两种 五种（Broadcast/P2P/NBMA/P2MP/Loopback）

📌 一句话总结：ISIS兼容性好且更适用于扁平化运营商网络，基于设备划分区域（整台设备一个区域）、基于数据链路层工作；OSPF更适用于灵活园区网，基于接口划分区域、基于IP层工作。

2. ISIS区域与邻居规则

ISIS区域特点：

  • Level 1区域：由所有Level 1路由器组成，建立邻居要求区域ID必须一致。
  • Level 2区域：由所有Level 2路由器组成，建立邻居区域ID不需要一致。
  • Level 1-2路由器：连接Level 1和Level 2区域，相当于OSPF的ABR。

📌 一句话总结：ISIS的Level 1建邻居要求区域ID一致，Level 2不要求一致，与OSPF的"非骨干必须直连骨干"机制不同。

3. ISIS角色与OSPF对照

ISIS角色 对应OSPF角色 说明
Level 1 非骨干区域路由器 只维护本区域LSDB，通过Level 1-2访问外部
Level 2 骨干区域路由器 维护骨干层LSDB，所有Level 2路由器共同组成骨干
Level 1-2 ABR 同时连接Level 1和Level 2，进行区域间路由传递

📌 一句话总结：ISIS角色分Level 1（非骨干）、Level 2（骨干）、Level 1-2（ABR），Level 2所有路由器共同组成骨干区域，与区域ID无关。

4. ISIS术语对照

ISIS术语 OSPF对应术语 说明
IS（Intermediate System） Router 中间系统=路由器
ES（End System） PC/终端 终端系统=主机设备
IIH（IS-IS Hello） Hello包 发现和维护邻居关系
LSP（Link State PDU） LSA 链路状态协议数据单元，携带拓扑和路由信息
CSNP（Complete SNP） DBD 完整的链路状态摘要，DIS周期性发送
PSNP（Partial SNP） LSR + LSACK 部分的链路状态摘要，用于请求和确认LSP

📌 一句话总结：ISIS的IS=路由器、ES=终端、IIH=Hello、LSP=LSA、CSNP=DBD、PSNP=LSR+LSACK。

5. NET地址（网络实体标题）

全称：Network Entity Title

格式：区域ID + System-ID + SEL

示例：49.0001.0000.0000.0001.00

从后往前解析：

  • 00 → SEL（Selector），固定为 00，表示网络层服务
  • 0000.0000.0001 → System-ID（6字节），等同于Router-ID，全网唯一
  • 49.0001 → 区域ID（变长，1-13字节）

NET地址要点：

  • 区域ID是变长的（1-13字节）
  • System-ID固定为6字节，不能重复
  • SEL固定为 00

📌 一句话总结：ISIS的NET地址格式为"区域ID+System-ID+00"，从后往前解析：SEL固定00、System-ID六字节全网唯一、区域ID变长；不同设备的System-ID必须唯一。

7. ISIS邻居状态

ISIS的邻居关系只有三个状态，没有邻居和邻接之分：

状态 说明
DOWN 关闭状态
INIT 收到IIH，开始协商
UP 邻居关系完全建立

等同于OSPF的 DOWN → INIT → 2-Way（直接进入FULL）

📌 一句话总结：ISIS邻居状态只有DOWN-INIT-UP三级，没有OSPF中邻居与邻接的区分，建立后即为FULL状态。

8. ISIS的DIS（指定中间系统）

全称：Designated Intermediate System，相当于OSPF的DR

DIS与OSPF DR的核心差异：

对比项 ISIS DIS OSPF DR
作用 周期性发送CSNP（完整LSP摘要） 负责LSA同步，减少更新量
邻居关系 所有路由器直接建立邻接关系 所有路由器只与DR/BDR建立邻接
选举优先级 先比优先级（默认64），再比MAC地址（越大越好） 先比优先级（默认1），再比Router-ID（越大越好）
优先级为0 0也参与选举（优先级最低而已） 0表示不参与选举
备份机制 没有BDIS（无备份DIS，直接重选） 有BDR作为备份
抢占机制 支持抢占（新加入高优先级设备可抢占） 非抢占（DR选定后不重选）
Hello间隔 DIS的Hello时间是普通路由器的 1/3 DR和普通路由器Hello时间相同
故障检测 三次没有收到DIS的Hello则认为DIS失效，重新选举 BDR检测到DR失效后接替

📌 一句话总结：ISIS的DIS选举看优先级（0也参与）和MAC，支持抢占、无BDR备份；作用为周期性发送CSNP，所有路由器可直接建立邻接；DIS的Hello时间为普通路由器的1/3，三次未收到则重新选举。

核心内容：ISIS协议（认证、路由汇总、路由泄露）、路由匹配工具（ACL/前缀列表/Route-Policy）、双点双向重分布（次优路径/环路/Tag解决）

一、ISIS认证（三种层次）

ISIS认证分为三个层次，接口认证影响邻居建立，区域认证和路由域认证只影响路由学习。

1. 接口认证（邻居认证）

原理：认证密钥在 IIH（Hello）信息 中携带，直接影响邻居建立。两端密码不一致则无法建立邻居关系。

bash

[R4-GigabitEthernet0/0] isis authentication-mode md5 plain shangwen

2. 区域认证（Level 1认证）

原理：认证密钥在 Level 1的LSP、CSNP、PSNP 中携带，不影响邻居建立，但影响路由学习（LSP无法通过认证则不能同步）。

bash

[R1] isis 1
[R1-isis-1] area-authentication-mode md5 plain shangwen

3. 路由域认证（Level 2认证）

原理：认证密钥在 Level 2的LSP、CSNP、PSNP 中携带，不影响邻居建立，但影响路由学习。

bash

[R4] isis 1
[R4-isis-1] domain-authentication-mode md5 plain shangwen

📌 一句话总结：ISIS认证分三层——接口认证在IIH中携带影响邻居建立，区域认证（Level 1）和路由域认证（Level 2）在LSP/CSNP/PSNP中携带，不影响邻居但影响路由学习。

二、ISIS路由汇总

原理：在ISIS中配置路由汇总，减小路由表规模，同时自动生成指向null0的防环路由。

bash

[R1] isis 1
[R1-isis-1] address-family ipv4
[R1-isis-1-ipv4] summary 10.1.0.0 255.255.252.0 level-1 generate_null0_route

参数说明：

  • level-1：默认只对Level 2汇总，加此参数后同时对Level 1汇总
  • generate_null0_route：产生指向null0的防环路由

📌 一句话总结：ISIS路由汇总在IPv4地址族下用summary命令配置，默认只对Level 2汇总，可加level-1同时对Level 1汇总，并自动生成null0防环路由。

三、ISIS路由泄露（Level 2 → Level 1）

问题背景

  • Level 2 路由器可以接收所有区域的路由信息。
  • Level 1 路由器只能接收本区域的路由信息，通过一条默认路由访问其他区域。
  • 由于Level 1无法学习Level 2的明细路由，会忽略Level 2区域的开销，导致次优路径问题。

解决方案：路由泄露

将Level 2的明细路由泄露到Level 1区域，使Level 1路由器能够根据真实开销选择最优路径。

bash

[R3] isis 1
[R3-isis-1] address-family ipv4
[R3-isis-1-ipv4] import-route isis level-2 into level-1

📌 一句话总结：ISIS的Level 1只能通过默认路由访问其他区域，无法感知Level 2开销导致次优路径，需通过路由泄露（将Level 2路由引入Level 1）解决。

四、路由匹配工具

1. ACL匹配路由（局限性）

特点：

  • 可以匹配路由和数据（两者都能用）
  • 通过源地址部分匹配网段
  • ACL无法匹配掩码 → 192.168.1.0/24 和 192.168.1.0/27 无法分开匹配

2. 前缀列表（Prefix-List）

特点：

  • 只能匹配路由（不能匹配数据）
  • 相比ACL，增加了掩码的匹配能力

基础格式：

bash

ip prefix-list test index 20 permit 192.168.1.0 24 greater-equal 25 less-equal 32
  • test → 列表名称
  • 20 → 匹配顺序（从小到大）
  • 匹配 192.168.1.X，掩码 >=25 且 <=32

缩写规则：

写法 含义
permit 192.168.1.0 24 gre 27 掩码 >=27 且 <=32
permit 192.168.1.0 24 le 27 掩码 >=24 且 <=27
permit 192.168.1.0 24 掩码 >=24 且 <=24（精确匹配/24）
permit 0.0.0.0 0 匹配默认路由（0.0.0.0/0）
permit 0.0.0.0 0 le 32 匹配所有路由
permit 0.0.0.0 0 gre 32 匹配所有主机路由（掩码为32）

规则：只有单独不写 le 时 le 等于32，其余时候 le 都等于前面写的掩码值。

📌 一句话总结：ACL匹配路由无法区分掩码（/24和/27分不开），前缀列表专用于路由匹配且支持掩码范围控制（通过ge/le参数），写法上"permit 0.0.0.0 0"匹配默认路由、"permit 0.0.0.0 0 le 32"匹配所有路由。

五、Route-Policy（路由策略）

功能：相比 filter-policy 只能允许或拒绝路由条目，route-policy 除了允许/拒绝外，还可以调整路由的属性（开销、类型、Tag、优先级等）。

1. Route-Policy的基本结构

text

route-policy 名称 permit/deny node 节点号
  if-match 条件        # 匹配条件（可多个，AND关系）
  apply 动作            # 执行动作（修改属性）

2. 匹配条件（if-match）

匹配方式 说明
if-match ip address prefix-list XXX 匹配前缀列表
if-match ip address acl XXX 匹配ACL
if-match tag XXX 匹配Tag值
if-match cost XXX 匹配开销值

3. 执行动作（apply）

动作 说明
apply cost XXX 修改开销值
apply cost-type type-1/type-2 修改外部路由类型
apply tag XXX 修改Tag值（用于防环）
apply preference XXX 修改协议优先级

4. Route-Policy配置示例

需求：

  • 10.1.1.1/32 → type 2, cost 10
  • 10.1.2.0/27 和 10.1.3.0/24 → type 1, cost 100
  • 10.2.2.2/32 → type 2, cost 10
  • 192.168.12.0/24 → 拒绝
  • 利用route-policy默认拒绝所有的特性，拒绝192.168.12.0/24

配置：

bash

[R2] ip prefix-list host permit 0.0.0.0 0 greater-equal 32
[R2] ip prefix-list host2 permit 10.1.0.0 16 greater-equal 24 less-equal 27

[R2] route-policy shangwen permit node 10
[R2-route-policy-shangwen-10] if-match ip address prefix-list host
[R2-route-policy-shangwen-10] apply cost 10

[R2] route-policy shangwen permit node 20
[R2-route-policy-shangwen-20] if-match ip address prefix-list host2
[R2-route-policy-shangwen-20] apply cost 100
[R2-route-policy-shangwen-20] apply cost-type type-1

# 注意：192.168.12.0/24没有匹配任何node，被默认拒绝

[R2] ospf 1
[R2-ospf-1] import-route rip 1 allow-direct route-policy shangwen

调用位置：route-policy 通常在路由引入时调用（除BGP外）。

📌 一句话总结：Route-Policy不仅可允许/拒绝路由，还能修改属性（cost/type/tag/preference），通过if-match匹配条件、apply执行动作，路由策略默认拒绝所有未匹配条目，通常在路由引入时调用。

六、双点双向重分布

场景：两个协议（如RIP和OSPF/ISIS）之间，在两台边界路由器上相互引入路由，形成"双点双向"。

1. 双点双向重分布引发的问题

① 次优路径问题

规律：谁弱谁次优（协议优先级数值大的容易产生次优）。

OSPF + RIP场景：

  • OSPF优先级为10（内部）或150（外部），RIP优先级为100
  • 当RIP路由被引入OSPF后，OSPF的外部路由优先级为150（不如RIP的100优），可能出现次优路径

解决方案：调整OSPF内部/外部优先级，防止次优路径。（思科/锐捷默认OSPF优先级都是110，问题更明显）

② 环路问题

形成条件：在出现次优路径的基础上，原本为RIP的路由被重新重分布回RIP，且开销值比原来的更好，导致RIP路由表中形成环路。

2. 解决方案——Tag（路由标记）

核心思想：为路由打上Tag标记，识别路由的来源，防止路由被重分布回源协议。

规划：

  • 从RIP进入ISIS的路由 → 打Tag 100（标记为"来自RIP"）
  • 从ISIS进入RIP的路由 → 打Tag 200（标记为"来自ISIS"）
  • 在将RIP路由引入ISIS时，拒绝Tag为100的路由（防止从RIP来的路由再回到ISIS）
  • 在将ISIS路由引入RIP时，拒绝Tag为200的路由（防止从ISIS来的路由再回到RIP）

配置示例：

bash

# ========== 边界路由器R4 ==========

# 定义Route-Policy：ISIS → RIP（从ISIS引入RIP时调用）
[R4] route-policy itr deny node 10
[R4-route-policy-itr-10] if-match tag 100                    # 拒绝Tag=100（来自RIP的路由，防止环回）

[R4] route-policy itr permit node 20
[R4-route-policy-itr-20] apply tag 200                       # 打上Tag 200标记

[R4] rip 1
[R4-rip-1] import-route isis 1 route-policy itr

# 定义Route-Policy：RIP → ISIS（从RIP引入ISIS时调用）
[R4] route-policy rti deny node 10
[R4-route-policy-rti-10] if-match tag 200                    # 拒绝Tag=200（来自ISIS的路由，防止环回）

[R4] route-policy rti permit node 20
[R4-route-policy-rti-20] apply tag 100                       # 打上Tag 100标记

[R4] isis 1
[R4-isis-1] address-family ipv4
[R4-isis-1-ipv4] import-route rip 1 route-policy rti

bash

# ========== 边界路由器R5（类似配置） ==========

[R5] acl basic 2000
[R5-acl-ipv4-basic-2000] rule deny source 10.1.1.1 0.0.0.0
[R5-acl-ipv4-basic-2000] rule permit source any

[R5-isis-1] address-family ipv4

3. 调整协议优先级（配合Route-Policy）

bash

[R5] route-policy youxianji permit node 10
[R5-route-policy-youxianji-10] if-match tag 100
[R5-route-policy-youxianji-10] apply preference 120

[R4-rip-1] import-route isis 1 route-policy itr

# ========== 边界路由器B（同样配置，Tag一致） ==========

# 两侧边界路由器的Tag规划必须一致：
#   tag 100 = 来自RIP（在ISIS中识别）
#   tag 200 = 来自ISIS（在RIP中识别）

📌 一句话总结：双点双向重分布防环的关键——两侧边界设备使用统一的Tag规划，在重分布时利用Route-Policy拒绝携带本协议Tag的路由，配合调整协议优先级解决次优路径。

第十六天

核心内容：策略路由（PBR）、BGP（边界网关协议）

一、策略路由（PBR）

1. 策略路由的产生背景

传统路由的局限：传统路由只能依赖于目标地址进行数据转发。但在某些特殊场景下，可能需要依赖于源地址进行转发（例如：学生走联通出口、老师走电信出口），此时需要策略路由（PBR） 实现定向转发。

策略路由的能力：可以匹配源IP、目的IP、报文长度等多个因素，实现灵活的定向转发。

📌 一句话总结：策略路由可以匹配源IP/目的IP/报文长度等多种因素进行定向转发，解决了传统路由只能依赖目标地址的局限。

2. 策略路由与路由策略的区别

对比项 策略路由（PBR） 路由策略（Route-Policy）
工作层面 转发平面（直接影响数据转发） 控制平面（影响路由表生成）
生效范围 仅影响本设备 可以通过路由传递影响其他设备
匹配依据 五元组等多字段 路由属性（前缀、Tag、开销等）
动作 指定下一跳、出接口 允许/拒绝、修改属性

3. 策略路由的注意事项

  1. 策略路由如果匹配不到，则走普通路由（策略路由优先于普通路由，但不覆盖）
  2. 策略路由调用位置一定是转发平面的入方向（数据包进入设备时应用）
  3. 策略路由只能影响到本设备（如果通过控制平面改开销是可以传递到其他设备的）

📌 一句话总结：PBR工作于转发平面，匹配不到则走普通路由，只能影响本设备且调用在入方向；Route-Policy工作于控制平面，可影响其他设备。

4. 两种需求的不同实现方式

需求 控制平面方案 转发平面方案
XX拒绝访问YY 过滤路由（学习不到YY的路由） ACL实现访问控制
XX走特定路径访问YY Route-Policy调整OSPF开销 PBR策略路由

5. PBR配置命令

bash

# 1. 定义ACL匹配流量
[R1] acl advanced 3000
[R1-acl-ipv4-adv-3000] rule permit ip source 192.168.1.6 0 destination 10.4.4.4 0

# 2. 创建策略路由
[R1] policy-based-route shangwen permit node 10
[R1-pbr-shangwen-10] if-match acl 3000
[R1-pbr-shangwen-10] apply next-hop 192.168.12.2

# 3. 在接口入方向调用
[R1] interface GigabitEthernet 0/0
[R1-GigabitEthernet0/0] ip policy-based-route shangwen

apply next-hop 与 apply default-next-hop 的区别：

动作 执行顺序 效果
apply next-hop 先看PBR，再看普通路由 强制指定下一跳
apply default-next-hop 先看普通路由，再看PBR 相当于默认路由，只有普通路由没有匹配时才使用

📌 一句话总结：PBR配置分三步——ACL匹配流量、Route-Policy定义动作（apply next-hop强制转发/default-next-hop做默认网关）、接口入方向调用；apply next-hop优先于普通路由，apply default-next-hop则相反。

二、BGP（边界网关协议）

1. BGP概述

全称：Border Gateway Protocol（边界网关协议） 作用：用于AS之间实现通信的外部网关协议（EGP）。

BGP的五大特点：

  1. 作为外部网关协议，只传递路由信息，相比OSPF安全性较高。
  2. 基于 TCP 179端口，更新可靠，且可以跨设备建立邻居。
  3. 是唯一支持超大型网络的协议，可支持万条以上的路由。
  4. 支持丰富的路径属性，实现灵活的选路。
  5. 采用增量更新（只发送变化的路由），节省带宽。

📌 一句话总结：BGP是AS间的外部网关协议，基于TCP 179端口可靠传输，支持超大型网络、丰富路径属性和增量更新。

2. BGP邻居类型

邻居类型 含义 所在AS 建立方式 默认TTL
EBGP邻居 AS之间的邻居 不同AS 通常采用直连接口建立 1（可修改）
IBGP邻居 AS内的邻居 相同AS 通常采用Loopback接口建立（可跨设备） 255

① EBGP邻居配置（直连接口）

bash

[R1] bgp 100                                    # AS号为100
[R1-bgp-default] peer 192.168.12.2 as-number 200   # 对端AS为200
[R1-bgp-default] address-family ipv4
[R1-bgp-default-ipv4] peer 192.168.12.2 enable   # 华三需手动激活IPv4

[R2] bgp 200
[R2-bgp-default] peer 192.168.12.1 as-number 100
[R2-bgp-default] address-family ipv4
[R2-bgp-default-ipv4] peer 192.168.12.1 enable

② IBGP邻居配置（Loopback接口）

bash

[R2] bgp 200
[R2-bgp-default] peer 10.4.4.4 as-number 200
[R2-bgp-default] peer 10.4.4.4 connect-interface LoopBack 0   # 强制源地址为Loopback
[R2-bgp-default] address-family ipv4
[R2-bgp-default-ipv4] peer 10.4.4.4 enable

[R4] bgp 200
[R4-bgp-default] peer 10.2.2.2 as-number 200
[R4-bgp-default] address-family ipv4
[R4-bgp-default-ipv4] peer 10.2.2.2 enable

关键点：使用Loopback建立IBGP邻居时，需强制改变源地址（connect-interface），双方配置一边即可。

bash

[R4] display bgp peer ipv4          # 查看BGP邻居关系

📌 一句话总结：EBGP邻居跨AS通常用直连接口建邻（TTL=1），IBGP邻居同AS通常用Loopback跨设备建邻（需connect-interface强制源地址），华三需在IPv4地址族下手动enable。

3. BGP邻居状态机

状态 说明
IDLE 空闲状态，初始状态
Connect 建立TCP三次握手连接
OpenSent 发送Open信息，携带参数（Router-ID、认证、AS号等）
OpenConfirm 确认Open信息中的参数
Established 已建立状态，双方认可对方参数，邻居建立成功

特殊状态：

  • Active：出现错误的状态，说明TCP三次握手建立失败。

📌 一句话总结：BGP邻居状态经历IDLE→Connect→OpenSent（协商参数）→OpenConfirm→Established（建立成功），Active表示TCP三次握手失败。

4. BGP路由发布（两种方式）

方式一：network 宣告

特点：

  • 不需要直连，只要本地路由表中存在即可宣告
  • 宣告时前缀和掩码必须和本地路由表完全一致

bash

[R1] bgp 100
[R1-bgp-default] address-family ipv4
[R1-bgp-default-ipv4] network 10.1.1.1 32

方式二：路由引入（import-route）

bash

[R2-bgp-default-ipv4] import-route ospf 1

📌 一句话总结：BGP发布路由有两种方式——network需本地路由表存在且前缀掩码完全匹配才能宣告，import-route直接引入其他协议路由。

5. BGP路由传递原则（下一跳行为）

原则：IBGP邻居之间传递路由时，下一跳不变。

问题：这可能导致下一跳不可达（例如：EBGP传来的路由下一跳在AS外，IBGP邻居无法到达）。

解决方案：在IBGP邻居上配置 next-hop-local，将下一跳改为本设备地址。

bash

[R2] bgp 200
[R2-bgp-default] address-family ipv4
[R2-bgp-default-ipv4] peer 10.4.4.4 next-hop-local

📌 一句话总结：BGP传递路由时IBGP邻居间下一跳默认不变，可能导致下一跳不可达，需用next-hop-local强制修改为本地地址。

6. BGP防环机制

① IBGP防环：水平分割

原则：IBGP邻居之间只能传递一跳，即从IBGP邻居收到的路由不会再传递给另一个IBGP邻居。

② EBGP防环：AS-Path

原则：每经过一个AS，AS-Path中记录当前AS号。如果收到一条路由，其AS-Path中存在自身的AS号，则丢弃该路由。

📌 一句话总结：BGP防环——IBGP靠水平分割（只传一跳），EBGP靠AS-Path记录路径（看到自己AS则丢弃）。

7. BGP路由黑洞及其解决方案

问题：BGP路由黑洞

中间设备（未运行BGP）没有去往目标网络的路由，导致BGP路由无法转发。

方案1：同步规则（不推荐）

将BGP路由重分布进入IGP（如OSPF），让IGP承载BGP路由。

bash

[R2] ospf 1
[R2-ospf-1] import-route bgp

不推荐原因：BGP路由信息量较大，OSPF可能无法承载这么多路由。

方案2：全互联建立BGP邻居（不推荐）

让中间设备通过BGP学习到路由。但由于IBGP水平分割，IBGP邻居只能传递一跳，必须全互联建立邻居。设备数量多时，邻居数非常庞大（n(n-1)/2）。

不推荐原因：邻居数量太大。

方案3：BGP路由反射器（RR，推荐）

原理：打破IBGP水平分割原则，让路由可以传递多跳。

反射器的关键原则：

  • 只需在反射器（RR） 上配置，其他设备不知晓反射的存在。
  • 反射原则：只有两端都是非客户端时，路由才不会传递（即非客户端↔非客户端不反射）。
  • 经过反射的所有BGP属性不发生变化。
  • 反射器打破水平分割，需新增防环机制：
  • Originator-ID：经过反射的路由记录起始路由器的Router-ID，若收到的路由Originator-ID与本地Router-ID一致则丢弃。
  • Cluster-List：经过反射器后记录RR的Cluster-ID，若RR收到路由发现自身Cluster-ID已在列表中则丢弃。

bash

[R3] bgp 200
[R3-bgp-default] address-family ipv4
[R3-bgp-default-ipv4] peer 10.2.2.2 reflect-client

可靠性：反射器是单点故障，可配置两台反射器做冗余。

📌 一句话总结：路由反射器通过打破IBGP水平分割解决黑洞，只需在RR上配置reflect-client，反射原则是"非客户端↔非客户端不反射"，通过Originator-ID和Cluster-List防环，可配置多台RR避免单点故障。

方案4：BGP联盟（BGP Confederation）

原理：在AS内部划分多个子AS，将原本的IBGP邻居关系变成变相的EBGP邻居关系，从而解决水平分割。

联盟规则：

  • 子AS只在本地AS中生效，其他AS不会感知。
  • 联盟内部的联盟EBGP间传递信息仍按IBGP形式传递属性（AS-Path除外）。
  • 联盟内部通过AS-Path防环，但子AS不影响路由选举（透明传递）。

分配原则：划分多少子AS，两两一组，多余的单独一个AS。

bash

# R2 - 子AS 1001
[R2] bgp 1001
[R2-bgp-default] confederation id 200                    # 联盟ID（对端感知的AS号）
[R2-bgp-default] confederation peer-as 1002              # 联盟内对端子AS
[R2-bgp-default] peer 192.168.12.1 as-number 100         # EBGP（外部）
[R2-bgp-default] peer 10.3.3.3 as-number 1002           # 联盟EBGP（内部子AS）
[R2-bgp-default] peer 10.3.3.3 connect-interface LoopBack 0
[R2-bgp-default] address-family ipv4
[R2-bgp-default-ipv4] peer 192.168.12.1 enable
[R2-bgp-default-ipv4] peer 10.3.3.3 enable
[R2-bgp-default-ipv4] peer 10.3.3.3 next-hop-local

# R3 - 子AS 1002（边界）
[R3] bgp 1002
[R3-bgp-default] confederation id 200
[R3-bgp-default] confederation peer-as 1001
[R3-bgp-default] peer 10.2.2.2 as-number 1001
[R3-bgp-default] peer 10.2.2.2 connect-interface LoopBack 0
[R3-bgp-default] peer 10.4.4.4 as-number 1002           # IBGP（同子AS）
[R3-bgp-default] peer 10.4.4.4 connect-interface LoopBack 0
[R3-bgp-default] address-family ipv4
[R3-bgp-default-ipv4] peer 10.2.2.2 enable
[R3-bgp-default-ipv4] peer 10.4.4.4 enable

# R4 - 子AS 1002
[R4] bgp 1002
[R4-bgp-default] confederation id 200
[R4-bgp-default] confederation peer-as 1001
[R4-bgp-default] peer 10.3.3.3 as-number 1002
[R4-bgp-default] peer 10.3.3.3 connect-interface LoopBack 0
[R4-bgp-default] address-family ipv4
[R4-bgp-default-ipv4] peer 10.3.3.3 enable

📌 一句话总结：BGP联盟在AS内划分子AS将IBGP转为联盟EBGP解决水平分割，联盟子AS仅本地生效、透明传递且不影响选路，配置需confederation id（对外AS号）和confederation peer-as（对端子AS）。

方案5：MPLS（多协议标签交换）

R3不需要配置任何协议，也不需要学习到这条路由，就可以解决黑洞。（MPLS通过标签转发绕过路由查找）

📌 一句话总结：MPLS通过标签转发机制，中间设备无需学习BGP路由也能转发数据，从根本上解决BGP路由黑洞（后续课程详讲）。

第十七天

核心内容：BGP路径属性与选路（Preferred-value/Local-preference/AS-Path/Origin/MED）、BGP路由聚合、BGP对等体组、BGP团体属性

一、BGP路径属性与选路

1. BGP选路概述

BGP默认情况下不进行负载分担，只选择一条最优路径。BGP通过多种路径属性来控制选路，常用的选路属性按优先级从高到低依次为：

  1. Preferred-value（华为私有，本地有效，最高优先级）
  2. Local-preference（AS内传递，越大越优）
  3. AS-Path（越短越优）
  4. Origin（i > e > ?）
  5. MED（越小越优）
  6. EBGP优于IBGP（EBGP路径优先）
  7. 下一跳度量值（越小越优）

负载分担条件：前八条选路规则一致时，才能实现负载分担。

2. Preferred-value（华为私有属性）

特点：

  • 华为私有属性，仅本地有效，不会传递给邻居
  • 值越大越优，优先级最高
  • 只能在入方向应用

① 主备方式配置

bash

[R4] bgp 200
[R4-bgp-default] address-family ipv4
[R4-bgp-default-ipv4] peer 10.3.3.3 preferred-value 100
# 从10.3.3.3收到的所有路由优先级设为100（高于默认值0），走主路径

② 负载分担配置（基于源IP匹配不同邻居）

需求：源IP 10.1.1.x 走R2，源IP 10.1.2.x 走R3。

bash

# 定义ACL匹配不同源地址
[R4] acl basic 2000
[R4-acl-ipv4-basic-2000] rule permit source 10.1.1.1 0.0.254.255
[R4] acl basic 2001
[R4-acl-ipv4-basic-2001] rule permit source 10.1.2.1 0.0.254.255

# 针对R2邻居的Route-Policy
[R4] route-policy R2 permit node 10
[R4-route-policy-R2-10] if-match ip address acl 2001
[R4-route-policy-R2-10] apply preferred-value 10
[R4] route-policy R2 permit node 20          # 放行其他所有路由

# 针对R3邻居的Route-Policy
[R4] route-policy R3 permit node 10
[R4-route-policy-R3-10] if-match ip address acl 2000
[R4-route-policy-R3-10] apply preferred-value 10
[R4] route-policy R3 permit node 20          # 放行其他所有路由

# 在BGP中调用
[R4] bgp 200
[R4-bgp-default] address-family ipv4
[R4-bgp-default-ipv4] peer 10.2.2.2 route-policy R2 import
[R4-bgp-default-ipv4] peer 10.3.3.3 route-policy R3 import

📌 一句话总结：Preferred-value是华为私有属性且仅本地有效、优先级最高、只在入方向生效；值越大越优，主备方式对邻居整体设置，负载分担方式通过Route-Policy结合ACL对特定路由设置不同值实现多路径分担。

3. Local-preference（本地优先级）

特点：

  • 公认必遵属性，在AS内部传递，越大越优
  • 影响出AS的流量选路
  • 可以在入方向或出方向应用

① 主备方式配置

bash

[R3] bgp 200
[R3-bgp-default] address-family ipv4
[R3-bgp-default-ipv4] default local-preference 150
# 将所有路由的本地优先级设为150（默认100），使本设备成为更优出口

② 负载分担配置

bash

# 定义ACL
[R2] acl basic 2000
[R2-acl-ipv4-basic-2000] rule permit source 10.1.1.1 0.0.254.255
[R2] acl basic 2001
[R2-acl-ipv4-basic-2001] rule permit source 10.1.2.1 0.0.254.255

# Route-Policy
[R2] route-policy lp permit node 10
[R2-route-policy-lp-10] if-match ip address acl 2000
[R2-route-policy-lp-10] apply local-preference 50

[R2] route-policy lp permit node 20
[R2-route-policy-lp-20] if-match ip address acl 2001
[R2-route-policy-lp-20] apply local-preference 150

[R2] route-policy lp permit node 30           # 放行其他路由

# 在BGP中调用（出方向）
[R2] bgp 200
[R2-bgp-default] address-family ipv4
[R2-bgp-default-ipv4] peer 10.4.4.4 route-policy lp export

📌 一句话总结：Local-preference在AS内传递、越大越优，影响出AS流量选路；主备方式用default local-preference全局设值，负载分担方式通过Route-Policy在export方向对不同路由设不同值。

4. AS-Path（AS路径）

特点：

  • 公认必遵属性，用于EBGP防环
  • 因为还需防环，AS-Path只增不减
  • 增加AS时需考虑后续是否会经过该AS，尽量增加自身AS
  • 可以影响进入本AS的路径（import），也可以影响离开本AS的路径（export）

注意：修改AS-Path需谨慎，可能影响防环机制。

bash

[R2] acl basic 2000
[R2-acl-ipv4-basic-2000] rule permit source 10.4.3.4 0.0.0.0

[R2] route-policy aspath permit node 10
[R2-route-policy-aspath-10] if-match ip address acl 2000
[R2-route-policy-aspath-10] apply as-path 200           # 添加AS 200到路径中

[R2] route-policy aspath permit node 20

[R2] bgp 200
[R2-bgp-default] address-family ipv4
[R2-bgp-default-ipv4] peer 192.168.12.1 route-policy aspath export

📌 一句话总结：AS-Path是公认必遵属性，用于EBGP防环，值越短越优；修改时只能增加不能减少，在export方向增加自身AS可使路由在其他AS选路中变得不优（路径变长），不推荐常规使用。

5. Origin（起源属性）

特点：

  • 公认必遵属性
  • 表示路由的起源方式，优先级顺序：i（IGP） > e（EGP） > ?（incomplete）
值 含义 优先级
i 通过network宣告 最高
e 通过EGP协议（如BGP早期版本） 次高
? 通过import-route引入 最低

📌 一句话总结：Origin是公认必遵属性，优先级顺序为 i > e > ?，network宣告优先级最高，import-route引入优先级最低。

6. MED（多出口鉴别器）

特点：

  • 可选非过渡属性
  • 值越小越优
  • 当这条路由是EBGP邻居本地直接发出的，会继承本地路由表中的开销值
  • 传递给EBGP邻居后，用于影响对方AS进入本AS的流量选路

应用场景：当两个AS之间有多个连接时，通过MED告诉对方从哪个入口进入本AS最优。

📌 一句话总结：MED是可选非过渡属性，值越小越优，用于影响对端AS进入本AS的流量选路；EBGP邻居发出的路由会继承本地路由表中的开销值作为MED。

7. EBGP优于IBGP

特点：

  • 思科/锐捷设备：EBGP优先级为20，IBGP优先级为200
  • 优先选择EBGP路径（经过的AS少，更可靠）

📌 一句话总结：EBGP路径优于IBGP路径（思科/锐捷EBGP 20 vs IBGP 200）。

8. 优选下一跳度量值低的路径

📌 一句话总结：到达目标网络，下一跳IGP度量值越低的路径越优，即经过直连或低开销链路的路径优先。

9. 负载分担条件

前提：前八条选路规则全部一致时，才能实现负载分担。

bash

[R4-bgp-default-ipv4] balance ibgp 2
# 开启IBGP负载分担，最大并行路径数为2

📌 一句话总结：BGP默认不负载分担，需要前八条选路规则完全一致时才能通过balance命令开启，负载分担后并行路径数由balance参数控制。

二、BGP路由聚合

1. 自动汇总（不推荐）

bash

[R1] bgp 100
[R1-bgp-default] address-family ipv4
[R1-bgp-default-ipv4] summary automatic

特点：

  • 汇总成主类掩码（A类/8、B类/16、C类/24）
  • 只能汇总引入的路由（import-route的路由）
  • 不推荐（不支持不连续子网，粒度太粗）

2. 手工汇总（推荐）

bash

[R1] bgp 100
[R1-bgp-default] address-family ipv4
[R1-bgp-default-ipv4] aggregate 10.1.0.0 255.255.252.0 detail-suppressed

参数说明：

  • detail-suppressed：抑制明细路由（只发布汇总路由，不发布明细）
  • 如果不加此参数，默认明细路由仍然发布（汇总+明细同时发布）

防环机制：配置聚合后，设备自动生成指向null0的防环路由。

📌 一句话总结：BGP路由聚合推荐手工方式，自动汇总只汇总引入路由且粒度太粗不推荐；手工汇总用aggregate命令，加detail-suppressed可抑制明细路由只发汇总，配置后自动生成null0防环路由。

三、BGP对等体组（Peer-Group）

本质：BGP配置的简化工具，将一组具有相同策略的邻居统一配置，减少重复命令。

bash

[R4] bgp 200
[R4-bgp-default] group shangwen internal          # 创建IBGP对等体组（internal）
[R4-bgp-default] peer shangwen connect-interface LoopBack 0
[R4-bgp-default] peer 10.2.2.2 group shangwen     # 将邻居加入组
[R4-bgp-default] peer 10.3.3.3 group shangwen

[R4-bgp-default] address-family ipv4
[R4-bgp-default-ipv4] peer shangwen enable
[R4-bgp-default-ipv4] peer shangwen reflect-client    # 组内统一配置反射器

对等体组的优势：

  1. 简化配置（一次配置，多次复用）
  2. 提高配置可读性
  3. 批量修改策略（修改组策略即影响所有成员）

📌 一句话总结：BGP对等体组是配置简化工具，将具有相同策略的邻居统一配置，提高配置效率和可维护性；创建组后对邻居执行的各种策略只需对组配置一次即可。

EBGP对等体组创建

bash

[R1] bgp 100
[R1-bgp-default] group shangwen external as-number 200   # 创建EBGP对等体组，需指定AS
[R1-bgp-default] peer 192.168.12.2 group shangwen

四、BGP团体属性（Community）

作用：类似于OSPF/ISIS的Tag，将具有相同特性的路由打上相同的Community值，便于后续策略的批量调用。

默认行为：BGP默认不发送Community属性，需手动开启。

配置示例

① R1：为特定路由打上Community标签

bash

[R1] acl basic 2000
[R1-acl-ipv4-basic-2000] rule permit source 10.1.1.1 0.0.0.0

[R1] route-policy comm permit node 10
[R1-route-policy-comm-10] if-match ip address acl 2000
[R1-route-policy-comm-10] apply community 100:1

[R1] route-policy comm permit node 20              # 放行其他路由

[R1] bgp 100
[R1-bgp-default] address-family ipv4
[R1-bgp-default-ipv4] peer 192.168.13.3 route-policy comm export
[R1-bgp-default-ipv4] peer 192.168.13.3 advertise-community   # 必须开启，才能发送Community

② R3：根据Community匹配路由并调整Local-preference

bash

[R3] ip community-list 1 permit 100:1              # 定义Community列表

[R3] route-policy lp permit node 10
[R3-route-policy-lp-10] if-match community 1
[R3-route-policy-lp-10] apply local-preference 150

[R3] route-policy lp permit node 20                # 放行其他路由

[R3] bgp 200
[R3-bgp-default] address-family ipv4
[R3-bgp-default-ipv4] peer 10.4.4.4 route-policy lp export

团体属性优势：

  • 跨设备传递路由标签（OSPF/ISIS的Tag仅在区域内有效）
  • 批量匹配和策略应用（一次定义，多次使用）
  • 灵活性高（可自定义团体值）

📌 一句话总结：BGP团体属性类似于Tag，为路由打上标签便于批量调用策略，需用advertise-community开启发送，接收端用community-list匹配后执行相应动作，支持跨设备传递。

第十八天

核心内容：IPv6过渡技术（手动隧道/自动隧道/6to4隧道）、VPN技术概述、GRE VPN、IPsec VPN（机密性/完整性/真实性）

一、IPv6过渡技术

1. 手动隧道（IPv6 over IPv4手动隧道）

原理：在IPv4网络上手工指定隧道的源和目的地址，建立点到点的IPv6隧道，用于IPv6孤岛之间的互联。

bash

[R2] interface Tunnel 0 mode ipv6-ipv4
[R2-Tunnel0] source 10.2.2.2
[R2-Tunnel0] destination 10.4.4.4
[R2-Tunnel0] ipv6 address 2001:24::2/64
[R2-Tunnel0] ospfv3 1 area 0

特点：

  • 手动指定源地址和目标地址
  • 支持组播，可运行动态路由协议（如OSPFv3）
  • 每条隧道需要单独配置

📌 一句话总结：IPv6 over IPv4手动隧道需手工指定源和目的地址，支持OSPFv3等组播路由协议，适用于IPv6孤岛间互联。

2. 自动隧道（6to4隧道）

原理：自动隧道只指定源地址，目标地址隐藏在目的IPv6地址中（通过内嵌的IPv4地址自动计算出隧道终点）。不管有多少条隧道，都只有一个Tunnel接口。

bash

[R2] interface Tunnel 0 mode ipv6-ipv4 6to4
[R2-Tunnel0] source 10.2.2.2
[R2-Tunnel0] ipv6 address 2002:0a02:0202:1::1/64
[R2] ipv6 route-static 2002:: 16 Tunnel 0

6to4地址格式：2002:IPv4地址:子网::接口ID

例如：源IPv4地址 10.2.2.2 → 转换为十六进制 0a02:0202 → IPv6地址前缀为 2002:0a02:0202:1::1/64

6to4隧道的重要限制：

  • 不能使用OSPFv3（因为OSPFv3依赖组播，而6to4隧道不支持组播）
  • 只能使用静态路由或BGP来传递路由

bash

[R2] bgp 100
[R2-bgp-default] peer 2002:a04:404:1::1 as-number 200
[R2-bgp-default] address-family ipv6
[R2-bgp-default-ipv6] peer 2002:a04:404:1::1 enable
[R2-bgp-default-ipv6] import-route ospfv3 1

6to4隧道中的IPv6地址计算：

十进制IP 十六进制 嵌入IPv6前缀
10.2.2.2 0a02:0202 2002:0a02:0202:...
10.4.4.4 0a04:0404 2002:0a04:0404:...

bash

[R2] ospfv3 1
[R2-ospfv3-1] default-route-advertise always

📌 一句话总结：6to4自动隧道只配置源地址（目标地址隐藏在IPv6地址中的IPv4部分），一个隧道接口服务所有目的地，但不支持OSPFv3（只能用静态/BGP），适用于没有固定公网IP的场景。

3. 手动隧道 vs 自动隧道对比

对比项 手动隧道 6to4自动隧道
配置复杂度 高（每条隧道单独配置） 低（一个接口即可）
隧道接口数 N条隧道N个接口 1个接口
目标地址 手工指定 隐藏在IPv6地址中自动计算
支持路由协议 ✅ 支持OSPFv3 ❌ 不支持OSPFv3
适用场景 固定IP、少量隧道 动态IP、大量隧道

二、VPN概述

1. VPN的核心思想

VPN的核心是隧道（Tunnel），隧道通过封装技术实现。无论哪种VPN，本质都是将数据包封装后在公网上传输。

📌 一句话总结：所有VPN的核心都是隧道技术，通过封装实现私网数据在公网上的安全传输。

2. VPN分类

VPN类型 适用场景 典型技术
LAN-LAN VPN 总部和分支机构互联 GRE VPN、IPsec VPN、MPLS VPN
Client-LAN VPN 在外出差的员工远程接入 SSL VPN

三、GRE VPN

全称：Generic Routing Encapsulation（通用路由封装）

1. GRE VPN的特点

优点 说明
✅ 配置简单 配置命令少，易于部署
✅ 支持组播 可以运行动态路由协议（OSPF、BGP等）
✅ 支持多种协议 可封装IPv4、IPv6等多种网络层协议
缺点 说明
❌ 点到点 每两个站点之间需要单独配置一条GRE隧道
❌ 不安全 不提供加密，数据以明文传输
❌ 固定公网IP 双方必须拥有固定的公网IP地址

📌 一句话总结：GRE VPN配置简单、支持组播和多协议，但不提供加密安全性不足，且为点到点模式需要双方有固定公网IP。

四、IPsec VPN

全称：IP Security（IP安全协议）

1. IPsec的核心目标

IPsec VPN能保证数据的三大安全性：

安全目标 含义 实现技术
机密性（Confidentiality） 保证用户数据不被非法获取 加解密算法
完整性（Integrity） 保证用户数据传递完整，不被篡改 散列算法
真实性（Authentication） 确认发送方和接收方的身份 身份认证

📌 一句话总结：IPsec VPN通过加密算法保证机密性、通过散列算法保证完整性、通过身份认证保证真实性。

2. 机密性——加解密算法

对称加密算法

特点 说明
原理 发送方和接收方使用相同的密钥进行加解密
优点 算法简单，加解密速度快，适合大量用户数据
缺点 密钥传输安全性得不到保障（密钥如何安全送达对端）
常见算法 DES、3DES、AES

非对称加密算法

特点 说明
原理 使用公钥+私钥配对。通过对方的公钥加密信息，只有对方用其私钥能解密
优点 安全性高，只有持有私钥的对方才能解密
缺点 算法复杂，加解密速度慢，不适合加密大量数据
常见算法 RSA、DH

IPsec的实际加密方式

混合使用两者：

  • 使用对称加密算法（AES）加密用户数据（因为数据量大，需要快）
  • 使用非对称加密算法（RSA/DH）加密对称算法的密钥（因为密钥量小，用非对称保证安全）
  • 这样既保证了数据加密速度，又保证了密钥传输的安全性

📌 一句话总结：IPsec用对称加密（AES/DES）加密用户数据（速度快），用非对称加密（RSA/DH）加密对称密钥（安全），兼顾性能与安全。

3. 完整性——散列算法

特点 说明
原理 通过散列算法计算数据的散列值（Hash值），相同输入有相同输出，弱碰撞性（不同输入几乎不可能产生相同输出）
作用 接收方重新计算散列值，与发送方带来的散列值对比，一致则说明数据未被篡改
注意 计算出的散列值本身也需要保证不被修改（通常与加密结合使用）
常见算法 MD5、SHA（SHA-1、SHA-256）

📌 一句话总结：完整性通过散列算法（MD5/SHA）实现，相同输入产生相同输出、不同输入几乎不会碰撞，但散列值本身需防止被篡改。

4. 真实性——身份认证

认证方式 原理 特点
公钥认证法 用自己私钥加密信息，对方能用对应公钥解开 → 身份确认（因为私钥只有自己持有） 安全性高，但计算量大
PSK预共享密钥 通信双方事先约定一个密钥，认证时双方校验是否一致 配置简单，但不适合大规模部署

📌 一句话总结：真实性通过公钥认证（用自己的私钥加密、对方用公钥解密验证）或PSK预共享密钥实现，确认通信双方身份合法。

5. 非对称加密的两个用途总结

用途 用谁的密钥 实现的功能
身份认证 用自己私钥加密 对方用我的公钥能解开 → 证明是我
机密性 用对方公钥加密 只有对方用自己私钥能解开 → 确保只有对方能看

第十九天

核心内容：IPsec VPN（体系结构、工作模式、密钥管理、SA/IKE）、IPsec完整配置、IPsec与NAT共存注意事项

一、IPsec VPN回顾与总结

1. IPsec的优缺点

类型 说明
优点 ✅ 安全性高（支持加密、完整性、身份认证）
缺点1 ❌ 配置复杂（涉及IKE、ACL、Transform-Set、Policy等多个组件）
缺点2 ❌ 消耗设备资源多，延迟大（加解密运算消耗CPU）
缺点3 ❌ 不支持组播，不能配置OSPF（只能用静态路由或BGP）

📌 一句话总结：IPsec安全性高但配置复杂、消耗资源且不支持组播（不能用OSPF）。

二、IPsec体系结构

1. 安全协议

协议 全称 支持的NSA能力 推荐度
AH Authentication Header（认证头） 仅完整性和真实性，不能实现机密性 ❌ 不推荐（不加密）
ESP Encapsulating Security Payload（安全封装荷载） 机密性 + 完整性 + 真实性全部支持 ✅ 推荐

📌 一句话总结：AH只认证不加密，ESP同时提供加密+认证+完整性，实际部署推荐ESP。

2. 工作模式

模式 场景 是否新增IP包头 推荐度
传输模式 主机到主机之间 ❌ 不新增IP包头 适用于端到端通信
隧道模式 私网到私网经过公网传输 ✅ 新增IP包头（外层新IP头+内层原IP包） ✅ 推荐（站点到站点VPN）

📌 一句话总结：传输模式不新增IP头适用于主机到主机，隧道模式新增IP头适用于站点到站点VPN（推荐）。

3. 密钥管理

方式 特点 推荐度
手工密钥（Manual） 节点多则配置量大，无生命周期，不安全 ❌ 不推荐
IKE（互联网密钥交换协议） 配置简单，自动协商密钥，安全性高 ✅ 推荐

📌 一句话总结：手工密钥配置繁琐且无生命周期管理不安全，IKE自动协商密钥配置简单安全性高（推荐）。

4. SA（安全联盟）

全称：Security Association（安全联盟）

SA的本质：通信双方之间的安全约定（包括加密算法、认证算法、密钥、SPI等）。这个约定没有特殊要求，只要双方一致即可。

SA的核心特性：

  • SA是单向的（每个方向需要一个SA）
  • 本地的出方向SA = 对方的入方向SA
  • 对方的出方向SA = 本地的入方向SA
  • 实际配置中，本地的出和入约定可以一致

SA的建立方式：

  • 手工方式建立
  • IKE方式建立（推荐）

📌 一句话总结：SA是通信双方的安全约定，单向存在（一出一入成对），只要双方一致即可，推荐通过IKE自动建立。

三、IKE建立SA流程

IKE：Internet Key Exchange（互联网密钥交换协议）

第一阶段：IKE SA建立（保护二阶段）

目的：为第二阶段建立安全的通道（加密二阶段的协商过程）。

两种模式对比：

模式 数据包数量 特点 适用场景
主模式（Main Mode） 6个包 安全性更高，身份信息加密传输 默认模式，推荐使用
野蛮模式（Aggressive Mode） 3个包 速度快，但身份信息明文传输 NAT穿透或对端IP不固定时使用

一阶段完成的三个任务：

  1. 协商加密参数（加密算法、散列算法、DH组等）
  2. 进行密钥生成（通过DH算法生成共享密钥）
  3. 进行身份认证（PSK预共享密钥或证书认证）

第二阶段：IPsec SA建立（产生用户使用的参数）

模式：快速模式（Quick Mode）

二阶段协商的内容：

  • 安全协议（ESP/AH）
  • 工作模式（传输/隧道）
  • 加密算法（DES/3DES/AES）
  • 散列算法（MD5/SHA）

📌 一句话总结：IKE分两阶段建立SA——一阶段主模式（6包）或野蛮模式（3包）协商加密参数并完成身份认证以保护二阶段，二阶段快速模式产生真正加密用户数据的ESP/AH参数。

四、IPsec完整配置命令

1. 第一阶段配置（IKE）

① 创建IKE提议（加密参数）

bash

[R2] ike proposal 1
[R2-ike-proposal-1] encryption-algorithm aes-cbc-256      # 选择加密协议（对称）
[R2-ike-proposal-1] authentication-method pre-share        # 身份认证采用预共享密钥
[R2-ike-proposal-1] authentication-algorithm md5           # 选择散列算法（完整性）
[R2-ike-proposal-1] dh group14                             # 选择非对称加密算法（密钥交换）

注意：以上信息都可以不配置，设备存在一个默认的default策略，但需确保双方取值一致。

② 创建预共享密钥策略（Keychain）

bash

[R2] ike keychain K1
[R2-ike-keychain-K1] pre-shared-key address 100.1.34.4 key simple shangwen
# 和100.1.34.4（对端公网IP）的共享密钥为shangwen

③ 创建IKE Profile（绑定上述信息）

bash

[R2] ike profile yijieduan
[R2-ike-profile-yijieduan] proposal 1                     # 强制指定只能用1建议项

五、IPsec与NAT共存的关键注意事项

问题描述

IPsec和NAT都调用在公网出接口，但存在执行顺序问题：

  • NAT先执行，IPsec后执行
  • 如果NAT先处理了IPsec的流量，数据包已被转换，IPsec无法正常封装

解决方案

在NAT的ACL中拒绝掉IPsec的流量，让IPsec流量先经过IPsec处理，不经过NAT转换。

bash

# 创建NAT ACL，拒绝IPsec流量
[R2] acl advanced 3001
[R2-acl-ipv4-adv-3001] rule deny ip source 10.1.1.1 0 destination 10.5.5.5 0
[R2-acl-ipv4-adv-3001] rule deny ip source 192.168.12.0 0.0.0.255 destination 192.168.45.0 0.0.0.255

# 允许其他需要NAT的流量
[R2-acl-ipv4-adv-3001] rule permit ip source 192.168.12.0 0.0.0.255
[R2-acl-ipv4-adv-3001] rule permit ip source 10.1.1.1 0.0.0.0

# 在公网接口调用NAT
[R2] interface GigabitEthernet 0/1
[R2-GigabitEthernet0/1] nat outbound 3001

执行顺序：

  1. 流量到达公网接口
  2. 先检查IPsec策略 → 匹配ACL 3000 → 走IPsec隧道（不经过NAT）
  3. IPsec不匹配 → 检查NAT策略 → 匹配ACL 3001 → 走NAT转换

📌 一句话总结：IPsec调用位置与NAT同在公网出接口且NAT先执行，必须在NAT的ACL中deny掉IPsec的感兴趣流，否则IPsec流量会被NAT转换破坏封装导致通信失败。
